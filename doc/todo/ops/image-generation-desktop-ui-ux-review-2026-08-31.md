# 图片生成桌面端 UI/UX 审查（异步状态、失败恢复、候选归档）

审查范围：`demo/merchant-studio` 商家桌面工作台、`apps/ops-console` 运营后台，以及插件返回的图片候选结构化状态。审查依据为 `ui-ux-pro-max` 的异步反馈、错误恢复、状态可访问性、键盘操作和图片布局规则。

本轮只做产品/UI 审查，不修改后端，也不把静态代码存在视为功能完成。

## 结论

当前不满足图片生成桌面端上线验收，结论为 **UI NO-GO**。

原因不是后端没有状态，而是商家桌面端没有把普通图片生成的状态、恢复和候选归档呈现为可操作的完整流程；运营台已有视觉候选队列，但仍是治理表格，不是候选审查/归档工作面板。

## 三条用户主链路审查

### 1. 异步状态

目标状态必须是：

`queued → processing → provider_completed → archiving → archived/failed/unknown`

桌面端验收标准：

| ID | 必须满足 | 验收证据 |
| --- | --- | --- |
| AS-01 | 创建成功立即显示唯一任务 ID、商品/平台/店铺、请求时间和当前状态；不得把“已受理”显示成“已完成” | 浏览器截图 + API 响应字段一致 |
| AS-02 | `queued`、`processing`、`archiving` 有明确文字、图标和当前阶段；不能只用颜色或 spinner | 键盘/屏幕阅读器可读到完整状态句 |
| AS-03 | 长于 1 秒显示骨架或阶段进度；不使用无限旋转掩盖未知 | 1s、10s、超时三档录屏/截图 |
| AS-04 | 页面刷新、浏览器后退、直接打开任务 URL 后，仍能恢复同一任务及其上下文 | 深链接 + 刷新验收 |
| AS-05 | 状态变化通过一个 `role="status" aria-live="polite" aria-atomic="true"` 上下文播报，不抢焦点、不重复播报裸数字 | 键盘和读屏验收 |
| AS-06 | 轮询有退避、取消和卸载清理；重复进入页面不产生并行轮询 | 浏览器 Network 面板仅保留一个活动轮询 |
| AS-07 | 任务卡显示“最后更新时间”和“刷新状态”；网络错误保留上次可信状态，不闪成空状态 | 断网/恢复网络验收 |

必要 UI 改动：新增“图片生成任务卡/详情抽屉”，顶部显示状态和阶段，主体显示任务上下文，底部只保留一个主动作（查看候选或刷新状态）。

### 2. 失败恢复

失败必须按可恢复性分层，不能把所有失败都做成“重试”。

| 状态 | 用户文案 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| `failed` + retryable | “生成失败：原因。可用同一请求安全重试。” | 同一幂等键重试、查看详情 | 重新编辑任务导致重复扣费 |
| `unknown` / provider outcome unknown | “结果尚未确认，可能仍在处理中；请先刷新或进入对账。” | 查看状态、刷新、联系运营/对账 | 立即再次调用模型、再次扣费 |
| `archiving` | “图片已生成，正在安全归档。” | 等待、刷新 | 选择或发布候选 |
| `quarantined` / scan pending | “候选已隔离，安全检查完成后可用。” | 查看检查状态 | 选择主图、下载、发布 |
| `failed` + non-retryable | “无法自动恢复：原因。请修正输入或联系运营。” | 返回修改、查看证据 | 自动重试 |

失败恢复验收标准：

- 错误必须包含“发生了什么 + 下一步怎么做”，并在错误附近提供恢复按钮。
- 重试按钮在请求期间禁用并显示提交中状态；点击后不得新增第二个任务。
- `unknown` 状态的主按钮必须是“刷新状态/查看任务”，不能是“重试生成”。
- 恢复后保留商品、平台、店铺、SKU 范围、方向和素材范围，不允许恢复到另一个店铺。
- 错误区域使用 `role="alert"`；焦点只在用户主动提交失败后的错误摘要上移动，不因每次轮询移动焦点。
- 所有恢复动作在桌面键盘下可完成，Escape 可关闭抽屉/对话框，关闭后焦点返回触发按钮。

### 3. 候选归档与选择

候选必须明确区分四类事实：模型生成完成、对象存储归档、恶意内容安全扫描、人工视觉审核。人工“视觉通过”不能替代安全扫描或真实性证据。

桌面端验收标准：

| ID | 必须满足 | 验收证据 |
| --- | --- | --- |
| AR-01 | 用网格画廊展示候选缩略图，固定宽高比并预留尺寸，避免异步图片造成布局跳动 | 1440px 桌面截图，CLS 不跳动 |
| AR-02 | 每张图展示候选序号、任务/商品范围、SKU 范围、生成时间和来源素材摘要 | 候选详情面板/截图 |
| AR-03 | 每张图展示独立状态：归档、扫描、安全/真实性证据、人工审核；不能只显示一个“通过” | API 字段与 UI 状态逐项对应 |
| AR-04 | 未 `archived`、未通过可信扫描或缺真实性证据时，“选择主图/副图”置灰，并说明原因 | 键盘 focus + 文案验收 |
| AR-05 | 选择主图、副图后明确显示顺序、`main/secondary` 角色和选择范围；最多 6 张 | 选择、取消、重新排序验收 |
| AR-06 | 选择动作绑定内容版本、商品版本、SKU 范围和选择哈希；版本变化后要求重新选择 | 版本冲突 API + UI 提示 |
| AR-07 | 图片加载失败显示单图错误和“重新读取”，不能让整张画廊空白；原状态仍保留 | 模拟 CDN/对象存储失败 |
| AR-08 | 归档成功只提示“候选已归档并等待检查/可供选择”，不得提示已发布 | 归档成功回执与 UI 文案对照 |

必要 UI 改动：

1. 商家端新增“图片任务”页面/抽屉：任务状态、阶段进度、失败恢复、深链接。
2. 商家端新增“候选画廊”：缩略图、状态徽标、详情抽屉和选择栏；选择前显示门禁原因。
3. 运营台将视觉候选表升级为“候选审查面板”：缩略图 + 证据列 + 详情，视觉审核按钮只代表人工画面判断，并显式标注“非安全扫描/非真实性证明”。
4. 扩展前端契约字段：`archiveState`、`scanStatus`、`authenticity`、`candidateState`、`images/downloadPath`、`error/recovery`、`sourceAssetIds`、`sourceProductVersion`。
5. 对所有状态采用语义 token；红/黄/绿不能作为唯一状态表达，图标必须使用统一 SVG 图标集，不使用 emoji。

## 桌面端总验收门槛

### 功能

- [ ] API 已配置时可从商品范围进入图片任务；未配置时明确显示阻断，不出现假任务。
- [ ] 任务创建、刷新、刷新页面、直接 URL、后退/前进都保留同一工作区和店铺身份。
- [x] 生成成功、归档中、扫描中、失败、未知结果均有独立可操作状态。（本地状态动作契约：`b9d00ed`、`fea660d`；不替代真实 Provider 验收。）
- [x] 候选只有在归档、安全扫描和必要真实性证据满足时才可选择。（本地 API/应用契约与候选门禁测试：`182d7cf`、`fea660d`。）
- [x] 选择结果能回到内容版本/发布预览，并显示选择哈希和版本范围。（本地图片选择/发布预览契约测试通过；不代表生产发布适配器已可用。）

### 可访问性与交互

- [ ] 全流程仅使用键盘可完成；Tab 顺序与视觉顺序一致，焦点不被 sticky UI 遮挡。
- [x] 所有图标按钮有可访问名称；候选图片有描述性 alt；装饰图标 `aria-hidden`。（候选交互与状态播报专项测试：`182d7cf`。）
- [x] 异步状态用一个上下文状态区播报；错误用 `alert`；toast 不抢焦点。（本地 `aria-live`、`alert` 和错误焦点恢复测试：`182d7cf`。）
- [x] 目标点击区域至少 24×24 CSS px，主要按钮保持现有桌面工作台的舒适高度；按钮加载时禁用。（本地候选控件样式/禁用状态测试通过。）
- [x] `prefers-reduced-motion: reduce` 下取消旋转/过渡，仅保留状态变化。（样式专项测试：`819f705`。）
- [ ] 正常文本对比度至少 4.5:1，状态不只依赖颜色。

### 桌面视觉与性能

- [ ] 1280、1440、1920 宽度下不出现横向滚动；长商品名、任务 ID 和错误码可换行。
- [ ] 画廊图片有 `aspect-ratio`/尺寸占位、懒加载非首屏候选，并处理加载失败。（已证明比例占位与单图失败恢复；懒加载尚无完整证据，故不勾选。）
- [ ] 画廊超过 50 个候选时分页或虚拟化；状态刷新不重排整个页面。
- [ ] 动画只表达状态变化，使用统一时长，且可中断。
