## Paper Tigers：不应挤占当前上线重点的风险

- “没有手机和平板适配就不能上线”：本项目是桌面运营工作台，不属于需求和阻断项。
- “所有 disabled 都应立刻解除”：缺批准目录、费率或授权时阻断是正确安全行为；需要完成商业决策与真实验收，不是删除守卫。
- “必须先把巨大 server 完全重写”：拆分有价值，但不是先修范围冲突和证据漏跑的前提；大重写会增加当前验证成本。
- “工具数量少于历史 README 就一定退化”：应检查当前 metadata、合同和获批能力；工具数不能代表成功工作流数。
- “看到一次 502 就能认定架构不可用”：本轮只确认一次权限关闭后重试恢复，根因尚未定位；保留事件并监控，不制造原因。

## Elephants：需要明确讨论、不能继续含糊的问题

1. 哪一份业务规范是当前有效基线？历史最终 PRD、现行 Skill、商业 PRD 与 README 的冲突需要唯一版本索引。
2. 当前计划卖给商家的最小真实交付到底是什么？文本/图片工具可见、fixture 成功与可计费交付不是同一状态。
3. 谁负责批准费率、模型预算和真实平台写入范围？工程/测试不能代替财务或商家作决定。
4. 谁对“真实 ChatGPT.app 上跑过”签字？当前连接诊断、桥接 mock 和字符串 gate 都不是该证据。
5. 发生 provider 已接收但结果未知时，谁承担对账和客户解释？自动重试/退款不能替代费用与回执归因。

## 准出原则

按[项目评审](project-review-2026-09-07.md)和[测试方案](test-strategy-2026-09-07.md)执行。授权契约、真实宿主/中转链、商业准入、关键零 skip 数据库测试或发布证据任一未满足，保持 NO-GO；不设置依赖未到位时无法兑现的上线日期。
