# 外部资源需求文档（小白执行版）

> 适用项目：大麦商家营销平台、ChatGPT/Codex MCP 插件、运营后台。
>
> 目标：明确哪些外部账号、服务和资质必须准备，如何申请，什么时候购买，以及什么证据才算真正完成。

## 1. 先看结论

不要一次性把所有服务都买齐。建议分三阶段：

1. **现在先准备开发联调**：一个云账号、一个域名、一个测试环境、测试数据库/Redis/对象存储、测试身份认证。
2. **上线前再申请生产能力**：企业主体、生产云资源、密钥管理、OIDC/SSO、真实平台开发者账号、支付商户、模型服务。
3. **通过真实验收后才发布**：六平台 OAuth/读写回执、支付回调、对象恢复、数据库 PITR、监控告警、回滚演练、ChatGPT 工作区发布。

ChatGPT 插件/MCP 本身不要求支付服务、平台店铺授权、企业数据库或企业云账号。它至少需要一个 MCP 服务端、endpoint 和必要的认证；ChatGPT 不能直接连接本地 MCP，远程环境要使用可访问的 MCP endpoint 或 Secure MCP Tunnel。Apps SDK 目前仍是预览能力。[OpenAI 官方 Apps SDK 说明](https://help.openai.com/en/articles/12515353-build-with-the-apps-sdk) [OpenAI 官方 MCP 应用说明](https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt)

## 3. 每项资源怎么申请

### 3.1 企业主体和付款账户（第一步）

**用途**：所有生产资源都应由公司或长期运营主体持有，避免以后无法转移域名、云资源、支付账户和平台应用。

**准备材料**：

- 公司营业执照或个体工商户证照；
- 法定代表人/负责人身份证明；
- 公司对公账户或可验证的企业付款方式；
- 公司统一邮箱，例如 `it@your-company.com`，不要用员工私人邮箱作为唯一管理员；
- 负责技术、财务和运营的联系人。

**操作**：

1. 先建立公司管理员邮箱和密码保管制度。
2. 用公司主体注册云厂商、域名、支付、平台开发者和身份服务账号。
3. 至少设置两名管理员，开启 MFA；不要共用一个账号。
4. 购买和申请记录统一保存：订单号、合同、账号归属、到期日、续费人。

**验收证据**：账号主体是公司、管理员可交接、MFA 已开启、付款发票抬头正确。

### 3.2 域名、DNS 和 HTTPS

**推荐做法**：购买一个主域名，例如 `your-company.com`，规划：

- `app.your-company.com`：商家工作台；
- `ops.your-company.com`：运营后台；
- `mcp.your-company.com`：ChatGPT/MCP 服务；
- `api.your-company.com`：后端 API；

**操作**：

1. 在正规域名注册商搜索并购买主域名。
2. 使用公司主体实名认证和公司付款。
3. 将 DNS 托管到云厂商或可信 DNS 服务。
4. 创建上述子域名，指向云负载均衡或网关。
5. 申请免费 DV TLS 证书并配置自动续期。

**验收证据**：浏览器 HTTPS 无证书错误；MCP endpoint 可访问；OAuth 回调地址与平台注册地址完全一致；证书能自动续期。

### 3.3 云服务器/容器托管

**小白建议**：先选择一个云厂商，不要同时购买阿里云、腾讯云、AWS。国内团队可优先比较阿里云或腾讯云；如果业务和数据合规要求在海外，再评估 AWS/GCP/Azure。

**购买顺序**：

1. 注册企业云账号。
2. 选择一个区域，生产环境不要频繁跨地域迁移。
3. 开通容器托管或 Kubernetes；预算有限时可先用一台云主机 + Docker，但必须保留迁移路径。
4. 配置负载均衡、私有网络、防火墙和只开放 80/443 的公网入口。
5. API、Worker、Merchant UI、Ops UI 分开部署；数据库和 Redis 不直接暴露公网。

**验收证据**：Docker 镜像可拉取、API/Worker 可启动、健康检查可用、故障后能重新拉起、生产密钥不在镜像和 Git 中。

### 3.4 PostgreSQL、Redis 和对象存储

**PostgreSQL**：选择云数据库 PostgreSQL，开启自动备份、跨可用区或副本、PITR。数据库账号至少分为应用账号、迁移账号和运营账号。

**Redis**：用于 OAuth state、短时会话、任务队列、限流和缓存。开启密码/TLS（云厂商支持时），不要把 Redis 暴露在公网。

**对象存储**：创建至少两个 bucket 或前缀：测试和生产。生产开启版本控制、生命周期、删除保护、服务端加密；上传流程使用隔离区、扫描后再进入 clean 区。

**验收证据**：

- 数据库完成一次备份和恢复；
- PITR 能恢复到指定时间点；
- Redis 重启后 OAuth state 和队列行为符合预期；
- 对象能上传、读取、删除、恢复，SHA-256 和大小一致；
- 数据库恢复不能被当作对象文件恢复的替代证明。

### 3.5 Secret Manager 和 KMS

**必须保存的密钥**：

- 数据库连接串；
- Redis 密码；
- OIDC client secret；
- 六个平台 OAuth client secret；
- 支付签名密钥；
- 模型服务 API key；
- 对象存储访问密钥；
- ChatGPT/MCP 网关的服务端密钥。

**操作**：

1. 购买/开通云 Secret Manager 和 KMS。
2. 按环境分开：development、staging、production。
3. 按服务分配最小权限，不让插件拿数据库、支付或平台原始 token。
4. 开启审计日志、轮换和撤销机制。

**验收证据**：仓库扫描不到生产 secret；日志和错误响应不包含 token；轮换后服务能正常运行；离职账号不能读取生产密钥。

### 3.6 OIDC/SSO

**用途**：只用于运营后台、内部成员登录、RBAC 和审计，不是 ChatGPT 插件协议本身的必需品。

**申请方式**：选择企业身份服务，例如云厂商身份服务、Auth0、Okta、Keycloak 托管方案或公司已有 IdP，创建一个生产应用。

**需要配置**：

- issuer/discovery URL；
- client ID 和 client secret；
- 登录回调 URL；
- logout URL；
- 用户组/角色映射；
- MFA 和短期会话；
- refresh token 或离线访问策略（如业务需要长期连接）。

**验收证据**：真实账号登录成功；无权限用户被拒绝；角色变更能生效；nonce/state 重放被拒绝；浏览器使用安全的 httpOnly cookie；生产不使用本地 Bearer pilot token。

### 3.7 ChatGPT 工作区和 MCP App

**如果只是开发测试**：可以先由有 Developer Mode 权限的账号测试；Pro 用户可构建 Apps SDK 应用，完整 MCP 写入能力当前主要面向 Business 和 Enterprise/Edu 工作区。

**如果要企业内部发布**：

1. 购买/开通 ChatGPT Business 或 Enterprise/Edu 工作区。
2. 由管理员在工作区设置中启用 Developer Mode。
3. 提供 MCP endpoint 和元数据。
4. 选择认证方式；需要用户身份隔离时使用 OAuth/OIDC，不要使用全员共享静态 token。
5. 扫描工具，测试只读、写入、确认和错误路径。
6. 管理员审核并发布；发布后的工具定义可能需要重新审核更新。

**当前项目特有要求**：

- 使用 `mcp.your-company.com/mcp` 这类稳定地址；
- 插件只暴露商家工具，不暴露 `ops.*` 和运营敏感工具；
- 插件不得保存平台密码、平台 access token、数据库密码或 OpenAI 管理密钥；
- 生成、批准、充值、发布等副作用操作必须保留人工确认；
- 只读自动化和写入交互必须分开。

**验收证据**：工具清单符合预期；越权工作区被拒绝；用户 A 看不到用户 B 的店铺；写操作出现确认；撤销授权后调用立即失效；MCP 日志有 request/trace 但没有 secret。

### 3.8 六个平台开发者账号和测试店铺

平台必须逐个申请，不能用一个平台的 OAuth 代替其他平台：

| 平台 | 需要申请的主体 | 首批申请范围 |
|---|---|---|
| 京东 | 京东开放平台开发者/应用 | 商品读取、SKU、库存价格、状态、媒体和测试写入 |
| 淘宝 | 淘宝开放平台应用 | 商品读取、SKU、状态、测试写入 |
| 天猫 | 天猫/淘宝开放平台相应应用 | 独立确认天猫 schema、资质和权限 |
| 拼多多 | 拼多多开放平台应用 | 商品、SKU、状态、测试写入 |
| 小红书 | 小红书开放平台应用 | 先确认官方 API、字段和媒体能力是否开放 |
| 抖音 | 抖音电商开放平台应用 | 先确认官方 API、字段和媒体能力是否开放 |

**通用材料**：企业证照、应用名称和描述、官网域名、隐私政策、服务协议、OAuth 回调 HTTPS 地址、联系人、业务场景说明、最小权限清单、测试店铺。

**申请顺序**：

1. 先申请开放平台开发者主体。
2. 创建应用，填写官网和隐私政策地址。
3. 只申请最小权限，先读后写。
4. 配置固定 OAuth callback。
5. 申请测试店铺或沙箱权限。
6. 完成授权、换 token、刷新 token、撤权。
7. 完成商品读取、媒体上传、写后回读和错误码记录。

**重要**：平台账号授权必须在平台官方页面完成，商家不能在 ChatGPT 对话中输入平台密码或 token。小红书、抖音若没有真实官方能力证据，只能显示为待配置或只读，不能宣传为生产可写。

### 3.9 支付商户账号

**用途**：商家充值、支付回调、退款、查询、对账。ChatGPT 插件本身不需要支付账号。

**申请材料通常包括**：企业证照、法人信息、结算账户、经营范围、网站/应用介绍、隐私政策、服务协议、退款规则和客服信息。具体材料以支付服务商审核页面为准。

**申请顺序**：

1. 先确定收款主体和结算账户。
2. 申请微信支付、支付宝或合规聚合支付服务商的企业商户号。
3. 配置支付回调 HTTPS 地址。
4. 配置签名、公钥/证书和退款权限。
5. 用沙箱或小额真实订单验证支付、重复回调、退款和对账。

**验收证据**：支付回调签名通过；重复回调幂等；订单状态不会只因前端返回而变成成功；退款和对账可追踪；测试订单不会被标记成生产到账。

### 3.10 模型服务

当前项目的商家插件不应让商家填写 OpenAI API key 或模型中转地址。模型费用由平台侧统一管理和计量。

**需要准备**：

- 一个由平台公司持有的模型服务账号或合规中转服务；
- 独立的 production project/key；
- 文本、图片、OCR、视频模型的可用性和价格证据；
- 预算上限、超额保护和审计日志。

**如果直接使用 OpenAI API**：由平台公司在 OpenAI API 平台创建项目和服务账号 key，key 只放 Secret Manager；不要放在插件、浏览器或 Git。OpenAI 官方 API 快速入门说明了 API key、计费和模型调用的基本流程。[OpenAI API 官方快速入门](https://platform.openai.com/doc/quickstart/make-your-first-api-request)

**验收证据**：五模态实际请求成功；成本可计量；超预算阻断；失败可重试但不重复扣费；用户看不到服务端 key；模型输出不能绕过事实确认、审核和发布门禁。

## 4. 推荐的购买/申请顺序

### 第 1 周：只买最少资源

1. 公司管理员邮箱和密码管理器；
2. 一个云厂商企业账号；
3. 一个主域名；
4. 测试云主机或容器环境；
5. 测试 PostgreSQL、Redis、对象存储；
6. 测试 MCP endpoint；
7. 一个测试身份账号。

这一阶段只验证：网站能打开、MCP 能连接、插件能调用只读工具、数据能隔离、Docker 能启动。

### 第 2 阶段：上线前申请

1. 生产 Secret Manager/KMS；
2. 生产 OIDC/SSO；
3. 生产 PostgreSQL/Redis/对象存储及备份；
4. ChatGPT Business/Enterprise 工作区（若企业内部发布）；
5. 先申请京东、淘宝、天猫、拼多多测试应用；
6. 再申请小红书、抖音并核实官方能力；
7. 支付商户；
8. 模型服务生产项目；
9. 监控、告警和 on-call 联系人。

### 第 3 阶段：真实上线验收

只有以下证据齐全才允许上线：

- 生产域名、HTTPS、MCP endpoint 可用；
- 真实 OIDC 登录、RBAC、撤权和重放保护通过；
- 六平台逐个完成授权和能力 preflight；
- 至少一个真实测试店铺完成读、写、媒体上传、写后回读和撤权；
- 支付真实小额订单、重复回调、退款和对账通过；
- 模型、对象存储、数据库和 Worker 的生产凭据由托管 Secret 提供；
- 数据库 PITR、对象恢复、队列恢复和回滚演练通过；
- 监控告警和 on-call 值班明确；
- ChatGPT App 工具清单、权限、确认弹窗和隐私政策审核通过；
- 生产发布版本、镜像摘要、迁移版本和回滚包已签署并留档。

## 5. 个人先买，之后转企业，可以吗？

**开发阶段可以，但只限低风险资源**：测试域名、测试云主机、测试数据库、测试模型额度可以暂时由个人购买，前提是服务商支持主体/账号转移，并且不放真实商家数据。

**不建议个人持有以下生产资源**：

- 主域名和 DNS 管理权；
- 生产云账号；
- 支付商户号和结算账户；
- 平台正式 OAuth 应用；
- 生产数据库、对象存储和 KMS；
- ChatGPT 企业工作区管理员账号；
- 生产模型服务和 API key。

原因是这些资源往往涉及实名、合同、结算、数据归属和不可直接转移的审核关系。最稳妥的方案是：现在就用企业主体申请生产相关账号；个人账号只做短期本地/测试验证。

## 6. 当前项目还缺什么

根据当前仓库的生产审计，代码和本地 Docker 联调已经具备基础闭环，但生产仍缺真实外部证据，主要是：

1. 正式云环境和托管 Secret；
2. 真实 OIDC gateway、签名断言、nonce 重放拒绝；
3. 六平台真实 OAuth、字段/媒体能力和写后回读；
4. 真实支付、退款、查询和对账；
5. S3-compatible 对象存储的 versioning/lifecycle/KMS/扫描/恢复；
6. PostgreSQL PITR、容量、锁等待、副本延迟和恢复演练；
7. 生产 Worker 身份、监控、告警和 on-call；
8. ChatGPT 工作区的真实 MCP App 扫描、权限审核和发布；
9. 真实环境 release、canary 和 rollback 证据。
