# 商家营销平台商业化与运营后台 PRD

## 1. 结论

平台采用“工作区订阅 + 任务额度 + 高成本能力加购”的商业模型。

- 工作区是计费主体，也是店铺、平台授权、商品和任务的隔离边界。
- 套餐价格按人民币元存储，精确到两位小数。
- 内容生成、图片生成、批量同步等能力消耗任务额度。
- 充值钱包只作为支付和退款账务能力，不作为唯一的商业模型。
- 店铺和平台配置由运营后台调整，商家只能管理自己工作区内的授权范围。

### 模型供应商边界（上线必选）

- 模型中转站由平台统一采购、配置和保管，商家不得填写或绑定自己的地址、Key、模型。
- Codex App 免费版只作为插件宿主和 MCP 入口；插件业务请求由平台 API/Worker 使用平台 Vault 中的凭据调用模型。
- 平台 Key 不得进入 MCP 参数、Codex 上下文、插件返回值、日志、导出文件或运营前端。
- `MODEL_RELAY_BASE_URL`、`MODEL_RELAY_API_KEY`、`AI_MODEL` 和图片模型变量只能由部署密钥系统注入；所有模型请求必须经 HTTPS 自有中转站，未配置时生产请求 fail-closed。
- 平台承担模型中转站成本，商家按套餐任务额度和高成本能力加购付费；模型成本、配额和供应商健康度由运营后台查看脱敏 readiness。
- 详见 [平台模型与计费策略](../model/platform-model-billing-policy.md)。

## 3. 计费规则

### 3.1 任务计费

- 创建任务不扣费，避免用户在确认商品事实前产生争议。
- 用户确认商品事实后，任务进入可生成状态。
- 首次内容生成成功时扣除 1 个任务额度。
- 失败、超时、供应商不可用不扣额度；重复请求使用幂等键。
- 图片生成、批量生成和大批量同步可作为独立加购能力。
- 退款必须关联原始扣费流水、任务 ID、操作者和原因。

### 3.2 并发与超额

- 使用中的任务额度、剩余额度、订阅状态必须在服务端判断。
- 超过额度时返回明确的 `QUOTA_EXCEEDED`，不能静默降级为免费执行。
- 额度扣减必须原子化，使用 `workspace_id + idempotency_key` 防止重复扣费。

## 4. 运营后台模块

### 4.1 商户与用户

- 工作区列表、当前套餐、订阅状态、到期时间、店铺数和额度使用量。
- 用户角色：workspace_owner、merchant_admin、operator、support、finance、platform_ops。
- 支持冻结工作区、恢复工作区、查看风险标记和操作审计。
- 工作区冻结/恢复属于高风险运营操作，生产环境仅 workspace_owner、merchant_admin、platform_ops 可执行，且必须记录操作者、前后状态、时间和原因。

### 4.2 套餐与价格

- 套餐目录、月价、年价、店铺额度、任务额度、加购项。
- 生效时间、失效时间、灰度范围和变更原因。
- 套餐变更不能覆盖历史订单；订单保存当时的价格快照。
- 所有金额使用 `NUMERIC(12,2)`，接口字段使用 `*_price_cny`。

### 4.3 平台与店铺

- 平台开关：京东、淘宝、天猫、拼多多。
- 平台展示名、店铺别名、授权状态、授权范围、最后同步时间。
- 关闭平台后禁止新建任务和新发布，但保留历史数据和审计记录。
- 授权凭证只保存引用，不在运营后台展示 access token 或 refresh token。

### 4.4 账务与退款

- 充值订单、支付回调、消费流水、退款流水、余额和对账状态。
- 支付成功只能由服务商签名回调确认。
- 退款需要权限、原因和原始流水关联。
- 财务和运营权限分离，运营不能直接修改已支付金额。

### 4.5 数据与隐私

只采集完成业务所需的信息：

- 主体身份：用户 ID、工作区 ID、角色、登录会话。
- 商家资料：品牌、联系人、店铺和经营偏好。
- 平台授权：平台、远程账号、授权范围、状态、过期时间。
- 计费信息：订单、支付状态、金额快照、退款记录。
- 产品行为：任务创建、生成、审批、发布、失败和反馈事件。

禁止采集或展示密码、支付密钥、完整平台 token、无关通讯录和无业务必要的个人信息。

相关持久化表：

- `workspace_commercial_settings`
- `workspace_platform_settings`
- `workspace_usage_ledger`
- `workspace_subscriptions`
- `workspace_subscription_orders`
- `workspace_members`

运营后台实现：

- `apps/ops-console` 是独立的 Ant Design 管理端，不进入 Codex 插件用户端。
- 后台通过 `/mcp` 读取和修改工作区配置，支持套餐价格、额度、平台启停、展示名和店铺别名。
- 后台金额以元展示并提交两位小数，服务端负责最终校验。
- 运营后台支持 Bearer token、工作区 grant、成员角色调整、充值退款和账单下载；token 只保存在当前浏览器，不进入构建产物。
- 渠道漏斗只记录工作区、渠道、套餐、订单业务事件和时间，不采集支付密钥、完整平台 token 或无关个人资料。
- 订阅订单保存下单时的套餐、金额、店铺额度和任务额度快照，运营改价不影响历史订单。
- 订阅订单额外保存支付金额、优惠券编码、加购编码和渠道来源；升级订单区分目标套餐原价与本次支付补差价。
- 成员角色包括 `workspace_owner`、`merchant_admin`、`operator`、`support`、`finance`、`platform_ops`；生产环境的商业、平台和成员写操作必须由角色门禁放行。
- 平台运营总览只展示当前 Bearer token 授权的工作区，不允许使用 wildcard 绕过租户边界。
- 钱包退款关联原充值订单，只新增不可变退款流水，不修改原充值流水；同一订单退款幂等。

## 7. 核心指标

- 激活率：注册后完成首个商品事实确认的工作区比例。
- 首次价值时间：从注册到首次生成成功的时间。
- 额度消耗率：已消耗任务额度 / 套餐任务额度。
- 付费转化率：Trial 到付费套餐的转化率。
- 续费率：到期后继续付费的工作区比例。
- 平台连接成功率、同步成功率、内容生成成功率。
- 退款率和人工介入率。

## 8. 验收标准

- 修改价格后，新订单读取新价格，历史订单金额不变。
- 修改店铺额度后，服务端额度判断立即使用新配置。
- 关闭平台后不能创建新平台任务，但历史任务可查询。
- 平台开关验收已接入 MCP/REST 单任务和任务组创建门禁；关闭平台返回 `PLATFORM_DISABLED`，历史任务和审计保持可读。
- 并发更新使用旧 `revision` 时返回冲突，不覆盖新配置。
- 授权 token、支付密钥和用户敏感信息不出现在接口响应和日志中。
- 每次价格、额度、平台和退款操作均可追溯到操作者、时间、旧值、新值和原因。
