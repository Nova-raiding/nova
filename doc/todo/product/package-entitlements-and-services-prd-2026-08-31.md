# 商家营销插件套餐、权益与服务履约 PRD

状态：产品评审通过，待实现；不代表生产可售或上线通过
版本：1.0
日期：2026-08-31
Owner：产品
评审角色：产品、架构、前端、后端、测试、运营销售

## 1. 执行摘要

本 PRD 将三张套餐图片中的价格、软件权益和人工服务，从不可执行的销售描述，收敛为可版本化、可计量、可审计、可验收的产品合同。目标不是复刻图片 UI，而是让 ChatGPT 插件入口、API/MCP、模型中转、商家工作流、桌面运营后台、数据库/RLS、Worker 和发布门禁使用同一份套餐事实。

本 PRD 只批准目标态需求。当前生产判断仍为 **NO-GO**：模型密钥、六平台真实连接器、支付、托管对象存储和部分运行证据尚未完成；任何代码、fixture、静态页面或本地回退不得被写成生产能力。

## 2. 问题陈述

我们认为购买一次性基础搭建或月度套餐的商家，在开通、使用、计费、服务支持和发布时，无法获得与销售套餐逐项一致的权益与证据，导致用量不可解释、服务不可排期、超限不可强制、生产状态被误报，并产生超售、退款、合同和信任风险。

根因不是缺少若干页面，而是销售承诺、订阅权益、模型成本、人工服务、运行证据和发布安全没有统一的版本化商业契约。

### 2.1 目标用户

- 基础经营版：单品牌、中小商家和最多 5 个活动店铺。
- 增长版：最多 3 个活动品牌、15 个活动店铺的运营团队。
- 定制服务版：大型品牌、代运营、多品牌集团或素材服务商；全部“按需”权益必须在订单中落成具体值。
- 内部用户：销售、财务、实施、客服、客户成功、平台运营、规则审核和审计人员。

### 2.2 证据强度

| Offer 只含价格、店铺数和任务数 | 强 | 无法承载品牌、存储、创作额度、SLA 和人工服务 |

### 2.3 5 Whys

1. 套餐为何无法完整履约？因为部分权益只存在于图片。
2. 为何图片权益没有被执行？因为订阅只覆盖店铺和任务的局部字段。
3. 为何局部字段不足？因为没有不可变套餐版本、通用权益快照和服务账本。
4. 为何代码存在仍会误报？因为代码、fixture、已配置和真实交付没有统一状态。
5. 为何形成系统风险？因为商业承诺没有成为运行时的唯一事实源。

## 3. 已冻结产品决策

1. 图片中的“AI 创意点”统一改称“创作额度”。它是权益单位，不是人民币、Token、任务数或钱包余额。
2. 基础搭建验收通过后一次性发放 2000 点，有效期 365 天；幂等发放，不结转、不提现。退款后的未消费部分失效，已消费部分保留审计。
3. 取消图片中带问号的“每月赠送 500 点，持续一年”，不进入产品或合同。
4. 基础经营版每账期 2000 点，增长版 6500 点，定制版为订单快照中的明确正整数。
5. 每个模型动作使用版本化费率表。额度账本、模型用量账本和人民币成本账本相互关联但不可互相替代。动作失败或 provider 未执行必须释放预占。
6. 50GB 定义为每个 workspace 的十进制 50,000,000,000 字节总配额。原始文件、隔离对象、生成候选、视频和交付包均计入；只有带物理删除证明的对象才释放用量。
7. 品牌额度按 `active brand` 计数：基础 1、增长 3、定制合同值。店铺按唯一 `platform + remote account/store id` 的活动授权计数：基础 5、增长 15、定制合同值。
8. 降级绝不删除品牌、店铺、资产或历史数据。超额对象保持可读，阻止新增，进入 30 天宽限期和人工处理队列。
9. “自动上架”统一改为“自动准备、自动检查、人工确认后异步上架并对账”。无人值守发布、驳回后自动修改重发和绕过确认均禁止。
10. SLA 使用 Asia/Shanghai、周一至周五 09:00-18:00、中国法定节假日除外；4/2 小时指首次有效人工响应，不是解决时长。`waiting_customer` 暂停时钟并记录原因。
11. 六个平台统一为京东、淘宝、天猫、拼多多、小红书、抖音电商。平台必须按授权、商品读、内容写、媒体上传、状态回读五个能力分别展示 readiness。
12. API/ERP、专属审核和定制工作流只作为单独 SOW 项目。标准 MCP/OpenAPI 不等于已接入客户 ERP；首期不建设任意 DAG/低代码平台。
13. 图片中的价格、品牌/店铺/存储/服务额度、创作额度发放量、有效期和动作费率，均由桌面平台运营后台配置；表中数字只是首个目录版本的建议默认值，不是前端或服务端常量。
14. 配置生命周期为 `draft → validating → pending_approval → scheduled → active → retired | disabled`。编辑已生效配置只能创建新版本；禁止覆盖 active/history，禁止删除已被订单、账本或合同引用的版本。
15. 套餐与费率由商业运营起草，财务/风险批准；提交人与批准人必须不同。发布、停用、人工调账、额外赠点和高风险额度变更至少双人审批，并记录完整 diff、原因和影响预览。
16. 费率在动作预占时冻结 `rate_card_version_id + rate_rule_id`，结算、释放、退款和历史账单均沿用该版本。新旧版本生效边界上的并发请求各绑定唯一版本，永不按当前费率追溯重算。
17. 创作动作先消耗同一 workspace 内最早到期的可用套餐创作额度。点数不足时，只有商家已开启钱包按量兜底且本次金额确认票据有效，才允许“剩余点数 + 钱包短缺金额”原子联合预占；任一来源不足则全部预占回滚，动作不执行。“不允许部分成功”指动作不可拆分交付，不是禁止双资金来源。钱包金额按该动作 rate rule 引用的钱包价格版本独立计算，不把点数按汇率换成人民币；分别舍入点数和人民币分后再预占。失败按原资金来源原路释放/退款，额度不跨账期结转。
18. 定制版的“按需”只可用于目录展示。下单、激活、续费前，品牌、店铺、创作额度、存储字节、服务分钟、培训/复盘次数和首次导入数等可计量权益必须解析为有限整数：售卖为“包含”的权益必须是正整数，`0` 只表示明确不包含，绝不能代表未知或无限；`unlimited`、`null`、负数、Infinity 和“按需”字符串均为阻断。布尔/枚举能力使用明确枚举，不得绕过数量门禁。
19. 服务预约在开始前 24 小时可免费取消并释放预占；24 小时内取消或爽约默认结算预占时长，运营可凭证据审批冲正。服务权益不跨账期；跨账期预约绑定预约时权益周期，完成后按实际分钟、最高不超过已确认预约时长结算。具体政策可版本化，但订单快照不追溯。
20. SaaS 月套餐可独立于一次性基础搭建下单；涉及首次录入、规则安装或生产连接承诺时，订阅仅为 `active_restricted`，对应 capability 由其来源基础搭建订单或独立 SOW 的 restriction item acceptance 逐项解除，所有 blocking item accepted 后转为 `active`。拒绝验收不取消已合法提供的 SaaS 只读能力，退款按合同和支付策略处理。
21. 本 PRD 的新目录只销售月付。历史年付 grandfather 到当前合同期结束，但按月建立子权益周期；旧 `includedTasks` 不换算为创作额度。子周期以原合同 `period_start` 在 Asia/Shanghai 的日和时刻为周年锚点，第 n 期直接从原锚点加 n 个日历月，目标月无该日则截到月末（后续月份仍按原锚点日计算）；结束时间为下一锚点与 `paid_through` 的较早者，最后不足一月不补齐。切点位于周期中间时只迁移包含切点的同一期，不重新发放。续费时迁移到月付或另行审批、但仍按月发放权益的定制合同。

## 5. 一次性基础搭建服务

目标价格为 5000 元/次，作为独立实施服务订单，不与 SaaS 月费混为同一 SKU。

### 5.1 包含

- 工作区创建、插件连接和成员管理员绑定。
- 一次性 2000 创作额度，在验收通过后发放。
- 租户初始化和连接检查，不表述为私有化部署。
- 已通过生产 readiness 平台的基础规则、品类规则和活动规则包安装。
- 用户偏好、一个企业主体、套餐范围内品牌/店铺/商品的首次录入。
- 品牌基础资产、表达和视觉要求录入；客户负责资料真实性与权利。
- 一次标准培训：最多 2 小时、最多 10 人、一次改期、交付材料和纪要。
- 上线验收单和 30 天基础问题保修期。

### 5.2 不包含

- 品牌资料人工整理、大量历史素材清洗。
- 超出订单明确上限的额外品牌、店铺、商品和素材。
- 非标准平台、通用 ERP、私有化部署。
- 人工代做营销素材或保证平台审核、GMV、ROI、流量。

### 5.3 实施状态

`pending_payment → pending_install → workspace_bound → configuring → blocked | ready_for_acceptance → accepted | rejected → warranty → closed`

每次状态变更必须记录 workspace、订单、套餐版本、操作者、原因、时间和证据；`accepted` 必须包含真实 ChatGPT 插件入口、MCP、数据库、权限和签约能力的运行证据。

## 6. 功能需求

### FR-COM-001 不可变套餐版本与订单快照（P0）

- 套餐稳定 code 与不可变 version 分离；发布后的价格和权益不可原地修改。
- 每个订单、订阅账期和变更单冻结 `plan_version_id + checksum + 全量权益`。
- 客户端不得提交价格、额度或费率作为事实；服务端从有效套餐版本计算。
- 运营改价不追溯历史订单；历史来源推断的数据必须标记 `inferred`。
- 套餐版本发布时冻结其引用的创作额度政策、rate card、钱包价格、服务政策、SLA policy、工作日历和 readiness policy 的 version + checksum。被引用版本后来 retired/disabled 不影响已有订单与在途账本；新订单必须解析到当时全部 active 且相互兼容的版本，否则阻断。
- 新订阅和正常续费在新账期开始时发放完整周期权益。套餐变更默认下个续费点生效；即时升级仅发放“新套餐本账期总额度 - 本账期已发放总额度”的非负差额，沿用原账期结束时间且不回收已用权益；降级只在下个账期生效。
- 暂停期间不新发权益，已有 grant 仍按原到期日失效；恢复不重复发放。退款/取消停止未来发放，不删除消费历史；未结算 reservation 按 FR-COM-003 收口。
- 降级宽限从较低套餐快照 `effective_at` 起按绝对时间计算 30×24 小时，Ops 以 Asia/Shanghai 展示。宽限中升级/加购后立即重算准入；已不超额则清除阻断但保留宽限历史，仍超额则继续原 deadline，不重新起算。

验收：并发下单、重放回调、改价、升级、降级均保持历史快照；同幂等键异意图返回 409。

### FR-COM-001A 订阅状态与能力矩阵（P0）

新目录状态固定为 `active_restricted/active/paused/past_due/canceled/expired`；`trialing` 仅保留给迁移前历史订阅，新目录不创建试用。订单支付成功后，若合同包含尚未验收的首次搭建/生产连接则进入 `active_restricted`，否则进入 `active`。

| 状态 | 读取/导出已有数据 | 生成与新上传 | 平台读同步 | 平台写/发布 | 新服务预约 | 发放新周期权益/续费 |
|---|---|---|---|---|---|---|
| `trialing`（仅历史） | 是 | 仅 legacy capability snapshot 明确允许 | 仅 snapshot 明确允许 | 否 | 否 | 不补发；到期迁移或 expired |
| `active_restricted` | 是 | 仅未被 restriction item 阻断且通过真实模型、额度、存储门禁的能力 | 仅未被 restriction item 阻断 | 仅 checklist 中仍 blocked 的 capability 禁止；对应 acceptance 后该 capability 可用，但仍须 entitlement/readiness/人工确认并重新 prepare | 仅未被 restriction item 阻断 | 是 |
| `active` | 是 | 是，逐项 entitlement gate | 是 | 是，但必须交互确认 | 是 | 是 |
| `paused` | 是 | 否 | 仅读取已有回执，不发新同步 | 否 | 否 | 否 |
| `past_due` | 是 | 否 | 仅读取已有回执 | 否 | 否 | 否；支付恢复不重复发本周期权益 |
| `canceled/expired` | 是，按合同数据保留期 | 否 | 否 | 否 | 否 | 否 |

- 迁移 trialing 时，把可追溯合同/旧配置允许的生成、上传、平台读等逐能力冻结为显式 `legacy_capability_snapshot + evidence_ref + checksum`；无历史证据的能力为 blocked/manual_attention，绝不按套餐名或 UI 猜测。
- workspace owner/账务管理员可申请暂停、恢复或期末取消；支付回调驱动 past_due/恢复；合同到期驱动 expired；取消在已付周期末生效，在生效前使用 `cancel_at_period_end` 而不提前改变 active 状态。
- `paused/past_due` 恢复到此前的 `active` 或 `active_restricted`，同一权益周期不补发、不延长原到期日；跨过续费点后先完成支付和新周期原子激活。
- `active_restricted` 保存版本化 restriction checklist；每项绑定来源订单/SOW、阻断 capability、验收标准和 acceptance event。基础搭建、生产连接或其他独立 SOW 分别解除自己的 restriction；只有所有 blocking item 均 accepted 才原子转为 `active`。未购买基础搭建但购买生产连接 SOW 的客户以该 SOW acceptance 解限，不要求虚构基础搭建订单。内部状态、逐项 restriction、能力矩阵和 blocked reason 必须通过 MCP/API 返回，客户端不得猜测。

### FR-COM-001B 现存商业数据迁移政策（P0）

- 以每个 workspace 的 `commercial_v2_cutover_at` 为迁移切点。当前 Offer revision 生成不可变 `legacy` plan version；现有订单/订阅从价格、billing cycle、`includedStores/includedTasks` 生成带 `inferred=true` 的 period/snapshot，保留原始行 id 和 checksum。
- `includedTasks` 永不换算为创作额度。`legacy_task` opening 固定为：`granted=includedTasks`，`consumed=SUM(workspace_usage_ledger.units WHERE refunded=false AND 属于当前 usage_period)`，`remaining=max(0, granted-consumed)`；`monthly_tasks_used` 只作一致性校验。`consumed>granted` 时保留真实 consumed、记录 `over_limit_by` 并进入 manual_attention，不能截断或补发。opening checksum 覆盖 subscription/order/commercial settings 行版本，以及按 id 排序的本期未退款 usage ledger 行 hash；已 refunded 行不计 consumed，但保留迁移引用。
- 月付 `legacy_task` 只维持到当前月度子周期结束，不再续发。仍在 paid-through 内的历史年付合同继续在每个子周期按原 `includedTasks` 幂等发放 `legacy_task`，直到合同期末或客户明确同意提前迁移；每期 grant 绑定 legacy plan version、子周期、来源 checksum，唯一自然键为 `subscription_id + legacy_task + period_start`，绝不转换为创作额度。年付 paid-through 缺失时，只建立包含 cutover 的一个子周期，`ends_at=min(next_anchor, cutover_at+30天)`，标记 `inferred=true/manual_attention`，禁止后续自动发放或延长。客户选择并激活新目录版本后才获得创作额度。无 expiry 的旧 `platform/image_generation/bulk_sync` entitlement 按原余额迁成同名 legacy grant：月付在当前月度周期末到期，年付在当前已付合同期末到期；若历史 paid-through 缺失，则确定为 `cutover_at + 30 天`、标记 `inferred=true/manual_attention`，不得自动延长。旧余额的 granted/used/remaining 和来源行 checksum 全量保留，不扩张语义。
- 旧 usage/action/model/wallet/storage 账本不重写。切点生成可核对的 `migration_opening` 投影；切点后的退款/冲正写 V2 ledger 并引用原交易，不伪造逐笔历史。旧在途 reservation 继续在原账本收口并写关联事件，不重复预占。
- 切点前已创建的 pending order/change 继续由旧路径完成或显式取消；完成后立即生成 V2 snapshot。切点后新订单只允许 V2。回填自然键固定为 `source_table + source_id + target_kind + period`，重跑只校验 checksum，绝不重复发放。
- Expand 阶段旧系统为事实源且用户无变化；Backfill/Shadow 阶段仍读旧、V2 只比较并告警；Dual-write 阶段旧读为事实源、所有新写原子投影两侧；按 workspace Cutover 后 V2 为事实源，旧侧继续兼容投影至少一个完整月度周期。回退只切回已保持同步的旧读，不丢弃 V2 记录；差异非零、冲突未决或对账不平时禁止切换/回退。

### FR-COM-002 通用权益目录与准入（P0）

权益至少覆盖：创作额度、活动品牌、活动店铺、企业主体、首次导入商品/素材、存储、服务小时、培训次数、复盘次数、支持级别、API、专属规则、审核模板和定制工作流。

- 每个权益定义单位、周期、结转、超额、宽限和结算模式。
- 所有写入口在 API/MCP 服务端执行准入；前端隐藏按钮不算门禁。
- 计数和创建在同一事务中锁定权益快照，防止并发超卖。

### FR-COM-003 创作额度（P0）

- 流程为 `grant → reserve → settle | release → refund | expire | adjust`。
- 账本 append-only，余额是可重建投影。
- 每笔 grant/reservation/usage/settlement/release/refund/adjustment 永久保存并校验 `plan_version_id + entitlement_snapshot_id + rate_card_version_id + rate_rule_id + checksum`，以及 workspace、账期、动作、模态、provider request、任务、操作者、点数、真实成本和幂等键；不适用字段使用显式 reason，不得引用当前版本补算。
- 预占按“最早到期套餐额度优先”执行；点数不足且钱包兜底有效时，原子预占全部剩余点数和钱包短缺金额。点数按整数点的 rate rounding，钱包按整数分的 wallet pricing rounding 分别计算；任一预算或余额不足则全部释放，动作不执行。
- 钱包兜底默认关闭，只能由 workspace 账务管理员开启，授权最长 90 天，并设置单次和自然月人民币预算。每次动作仍需展示点数、钱包预计金额及最坏上限，并生成 10 分钟一次性确认票据；动作、费率、价格、预算、内容或 workspace 漂移使票据失效。撤销只阻止新预占，不中止已确认在途动作。
- 结算不得超过预占；实际点数/金额更低则按各自原来源释放差额。Provider 未执行、失败或取消全部释放；混合来源退款严格按原 settlement 的点数与钱包占比分别冲正，不从另一来源补偿。
- 已结算动作退款时，钱包原路退回原交易；点数先回原 grant。原 grant 尚有效则恢复可用，已经到期则创建有效期 30 天的 `refund_credit` grant，并引用原账期和原版本；不得进入普通新账期 grant 或改写过期记录。
- 月度额度不结转；账期末先阻止新预占，等待在途动作结算，再将未消费 grant 标记过期。跨账期预约或异步动作仍绑定发起时的权益周期。
- Provider 已成功但真实 usage/cost/账本结果未知时，点数与钱包保持 reserved，内容禁止交付，禁止重复调用；系统持续对账 24 小时后进入人工队列。人工只能凭 provider receipt/hash 和双人审批执行 `settle`、证明未执行后的 `release`，或按原来源 `refund/reverse`，不得静默释放、重复扣减或手工标记成功。
- 运营调账必须双人审批、原因和证据。

费率具体点数由 Ops 配置、财务/风险批准并发布为不可变 rate-card version；没有唯一有效费率时 fail-closed。

### FR-COM-006 Ops 套餐、创作额度与费率配置（P0）

- 套餐、基础搭建赠点、周期发放量、有效期、促销赠点和动作费率是独立但可引用的版本化配置域。
- 动作费率规则至少包含 canonical `action_code`、商家显示名、模态、计量单位（次/张/秒/千 token 等）、整数点数、舍入规则、最小/最大扣点、钱包计价引用、适用套餐/workspace/平台和生效区间。
- 费率解析优先级固定为：`workspace+platform` > `workspace` > `plan+platform` > `plan` > `platform` > `global`。每个优先级内部相同 action/time 不得重叠；解析后必须恰好一条规则，0 条或同级多条均 fail-closed，不自动选择更新时间较新的版本。
- 缺 action、单位、点数、舍入、生效时间或有效钱包引用时不得提交审批。所有生效时间使用带时区的绝对时间，Ops 默认以 Asia/Shanghai 展示；同一原子切换点只允许一个 scheduled version，竞争发布由 revision 锁拒绝。回滚通过创建并审批指向旧规则内容的新版本完成，不重新激活历史版本。
- Ops 必须支持列表、版本详情、草稿编辑、服务端校验、完整 diff、影响预览、提交、批准/驳回、定时生效、停用和历史审计。影响预览包含快照时间、受影响 workspace 数、近 30 日新旧点数差和潜在耗尽客户数；快照或目录 revision 变化后必须重算。
- 保存草稿不等于生效；批准人与提交人相同、预览过期、版本冲突或定制权益不具体时，服务端拒绝且保留草稿。
- 所有写请求包含 `expected_revision`、`idempotency_key` 和 `reason`。原子切换时，在途预占继续引用旧版本，新动作引用新版本；停用只阻止新动作，不改历史。
- 权限拆分为配置只读、草稿编辑、影响预览、审批、发布/停用、历史导出；canonical action catalog、单位、标签和限制均由服务端返回，前端不得维护副本。

验收：active v3 的编辑只生成 draft v4；v3 历史账单不变；重叠费率、同人审批和过期影响预览均被阻断；到点切换的并发用量各绑定唯一版本；停用后新动作明确 blocked，历史仍可查询。

### FR-COM-004 品牌、店铺、主体和首次导入额度（P0）

- 活动品牌、活动店铺和企业主体使用独立权益，不能互相替代。
- 同一远端店铺重授权不重复计数；跨平台同名店铺分别计数。
- 品牌从 `active` 起占用额度；进入 `archived` 且无进行中写任务后释放，删除中不释放。恢复 active 必须重新准入，超额则保持 archived。店铺在 OAuth 授权完成并绑定唯一远端 id 时占用；显式撤权且所有在途写任务收口后释放，token 过期、连接 degraded 或同店重授权不释放。已释放后恢复授权必须重新准入。
- 首次导入的商品和素材上限是套餐版本的必填正整数；正式目录未配置时不能销售或启动实施。
- 部分导入失败可恢复，不重复消耗额度；超额返回用量、上限和升级/加购动作。

企业主体属于一次性基础搭建订单权益，不由月套餐重复发放；标准搭建包含 1 个，额外主体必须是订单中的具体整数。主体自然身份为司法辖区 + 登记类型 + 规范化登记号的加密检索 hash；同 workspace 相同身份去重，同一法定主体可被不同 workspace 独立绑定但不得跨租户互见。`pending` 不占额，验证通过进入 `active` 时原子占额；更名不释放或新增，合并保留迁移链。只有注销/归档且无活动品牌、店铺、发布任务或法定义务引用时释放，历史不删除；恢复 active 必须重新准入。

首次导入额度属于一次性基础搭建订单，从 `configuring` 开始，到 `accepted` 或支付后 60 天中较早者到期；延期需要审批并形成新快照。商品按成功创建的 canonical product 唯一 id 计数，素材按扫描通过并持久化的内容 hash 计数，不按上传尝试、listing 数或失败项计数。重复外部 id/hash、更新、部分失败重试不重复计数；删除不返还额度，重新导入同一身份不重复计数。达到上限后可更新既有对象，不可创建新 canonical product/asset；每个成功对象以实施订单 + kind + canonical identity 作为幂等键。

### FR-COM-005 50GB 存储权益（P0）

- 上传前原子预占，成功后按真实字节结算，失败释放。
- 80% 预警，95% 强提醒；100% 阻断新增持久化对象的上传/生成写入，不阻断引用既有 clean/approved 资产的人工确认发布。
- 删除只有在对象存储返回删除确认或 HEAD 不存在证据后释放。
- 降级超额数据保持可读且不自动删除，并进入宽限期；写入门禁按下一条口径 A 执行。
- 30 天宽限到期后仍不删除、不解绑、不自动停用历史品牌、店铺、资产或账本；继续执行第 9 节逐权益门禁，直到升级/加购，或授权人员逐对象归档/停用后恢复到额度内。存储超额统一采用口径 A：只阻断会新增持久化对象的上传/生成，允许引用已存在且 clean/approved 的资产完成经人工确认的发布；宽限期内和到期后规则相同。
- 商家端显示总量、已用、预占、可用；Ops 显示对账状态但不提供跨租户对象下载。

### FR-SVC-001 服务订单、预约和工时账本（P1）

- 培训、1V1、复盘、陪跑、实施和验收均属于版本化服务 SKU。

### FR-SVC-002 客服 SLA（P0）

- 套餐快照包含支持级别、工作日历和首次响应分钟数。
- 工单创建后生成 deadline；状态、优先级、客户等待、合并、关闭和重开产生不可变 SLA 事件。
- 只有客服/实施人员发送且非自动回复、非内部备注，并包含面向客户的实质处理信息，才算首次有效人工响应。
- `waiting_customer` 仅能由授权客服在已提出明确客户行动项后设置并暂停；客户新消息或客服恢复处理时继续剩余时间。每次暂停、恢复、人工 override 都需要原因、审批规则和审计。
- 临期和违约进入告警、升级和月度报表；基础/增长目标达标率不低于 95%。
- 每个 SLA clock 永久绑定创建时的 policy/calendar/version/checksum；后续套餐或 policy 变更不追溯。首次响应前 15 分钟内、仅授权负责人可用“优先级纠错”事件从原 `created_at` 按新 policy 重算一次并审计，其他 override 不能伪改原 deadline。
- 合并工单保留各来源 clock，父工单对外采用最早 deadline；关闭前未响应仍计违约。已 resolved 工单重开创建新的 occurrence 和新 clock，使用重开时有效快照，历史 clock 不改。
- 月度 95% 分母为当月首次进入终态的所有应计首次响应 clock；仅合同明确不适用、重复且在首次响应前合并的子工单、经审计的测试工单排除。暂停时间不计，违约和未在月末终结但 deadline 已过的 clock 计失败，取数截止为次月第 3 个工作日。

### FR-SVC-003 复盘和专属负责人（P1）

- 增长版每月一次；定制版按订单选择每周或每月。
- 报告只能使用真实发布回执和授权业务数据；缺曝光/成交数据时明确不可评价。
- 定制客户负责人有生效期、备份人、容量上限、休假/离职交接和审计。

### FR-SVC-004 专属规则、审核模板、工作流和 API/ERP（P1/P2）

- 专属规则复用现有规则版本、作用域、审批和回滚，并增加 entitlement gate。
- 首期审核定制只支持受限模板、审批角色/顺序/超时/委托；安全硬门禁不可删除或绕过。
- 定制工作流和 ERP 通过独立项目记录触发、字段、认证、读写、速率、幂等、失败、UAT、回滚和责任矩阵。
- API 默认只读优先；写入需要双人审批、沙箱和生产 canary。

## 7. 商家端与桌面运营后台

### 7.1 ChatGPT 插件商家面

- 套餐与权益摘要卡：套餐版本、账期、生效期、品牌/店铺/存储/创作额度和服务余额。
- 双账本卡：创作额度与钱包/实际费用分开显示发放、已用、预占、退款、剩余、到期，并可按 operation/usage id 关联；复杂账单继续复用充值 MCP app。
- 能力卡：按平台和模态显示当前可用、需授权、阻断与证据。读取失败显示 error/unknown，不能渲染为 0、空数据或已通过。
- 超限卡：显示用量、上限、宽限期、升级/加购；不得链接隐藏的 Ops 工具。
- 发布确认卡：展示准确商品、平台、店铺、变更 diff、规则/素材/模型/配额 readiness、预计扣点/扣款、preview hash、过期时间、逐项确认范围、远端快照和最终回执；自动准备阶段绝不写平台。
- 服务卡：预约、剩余小时、复盘计划、工单 SLA 和负责人。
- ChatGPT 回复保持对话式结果和下一步，不把桌面 Ops dashboard JSON 直接搬入 structured content。

### 7.2 桌面 Ops 工作台

- 套餐目录采用“列表 → 版本详情 → 校验 → 差异/影响预览 → 审批 → 定时生效/下架”，覆盖价格及全部结构、创作和服务权益；前端不得保留生产套餐常量。
- 独立“创作额度与动作费率”工作台，覆盖 rate-card 生命周期、规则表、历史版本、影响预览、审批和审计，不能以单一模型 multiplier 代替。
- Workspace 权益实例与 override 页；双账本明细、对账和调账双人审批页。
- 实施订单、里程碑、验收、服务排期、预约冲突、工时和复盘页。
- SLA policy、工作日历、临期/违约队列和负责人容量。
- 平台×能力 readiness 矩阵、五模态、支付、存储、scanner、发布证据及证据抽屉。
- 所有平台级聚合脱敏；切换到明确 workspace 才能读写客户数据。

### 7.3 UI 状态、错误和接口契约

- 套餐：`draft/validating/pending_approval/scheduled/active/retired/disabled`；权益：`available/near_limit/exhausted/blocked/pending_effective/expired`。
- 账本：`pending/reserved/settled/refunded/reversed/failed/unknown/manual_attention`；服务：`unallocated/schedulable/scheduled/in_progress/completed/cancelled/no_show`。
- SLA：`on_track/at_risk/breached/paused/resolved`。readiness 分两层：证据生命周期为 `unconfigured/configured/unverified/canary_passed/expired/blocked/error/unknown`；面向商家 capability 投影为 `not_configured/read_only/ready/degraded/blocked/error/unknown`。只有未过期 `canary_passed` 且全部写依赖通过才投影 `ready`；仅读能力通过为 `read_only`；部分依赖/近期错误但安全能力仍可用为 `degraded`；证据 `expired/blocked` 投影 `blocked`；读取/聚合失败保持 `error/unknown`，不得转成 ready。
- 发布：`preparing/ready_for_confirmation/confirmation_expired/confirmed/publishing/delivered/rejected/unknown/manual_attention`。
- 所有状态同时使用文字和图标，不能只靠颜色；异步写入必须显示 loading→success/error。错误摘要可聚焦并链接字段，modal 关闭恢复焦点，表格/抽屉/tabs/modal 可用键盘完成。
- 复用并扩展 `workspace.commercial.get`、`workspace.usage.get`、`billing.status`、模型账单、存储、readiness、support、audit 和 `publish.prepare/confirm`；新增套餐/费率版本、权益快照/账本、服务预约、SLA policy/clock/violation、readiness evidence 契约。
- 所有写接口带 `expected_revision/idempotency_key/reason`；响应返回 server labels、units、limits、version、effectiveAt、nextAction 和 requestId，前端不得推导权益。403 返回缺失 capability/scope/requestId 及恢复动作。
- 权益快照对每类超额资源返回 `over_limit_count/grace_started_at/grace_ends_at/grace_status/enforcement/next_action`。商家卡显示宽限倒计时与到期阻断，Ops 队列提供逐对象人工归档/停用入口；不得把到期显示为已删除、可用或普通 exhausted。
- 桌面 Ops 与 ChatGPT 卡片按 WCAG 2.2 AA 验收：正文和状态文字对比度至少 4.5:1；图标按钮、表格行操作有可访问名称；键盘焦点始终可见且不被 sticky/overlay 完全遮挡；异步余额、readiness、审批和发布结果使用合适的 `aria-live` 或 `role=status|alert` 播报；字段错误通过 `aria-describedby` 关联对应字段。

## 8. 权限、审计与安全

- 所有 workspace 表带 `workspace_id` 并启用 RLS + FORCE RLS；repository 使用 workspace transaction。
- 套餐发布/停用、价格、费率、调账、赠点、服务时长、SLA override、负责人、规则和工作流均记录 actor、before/after、reason、evidence。
- 套餐、费率、workspace override、账本调整、服务排期、SLA 策略和 readiness 证据批准使用独立 capability；无权限时危险动作隐藏或进入清晰只读态，不能只显示 disabled。
- 普通商家不能修改权益或服务余额；客服不能发布套餐或调账；财务不能读取非必要客户内容。
- Worker 入队保存授权快照，执行前复核 revision；授权、权益、配置或内容漂移时拒绝执行。
- 日志、卡片和导出不得泄露平台 token、模型密钥、支付密钥和客户对象地址。

## 9. 异常、升级与降级

降级按权益类型选择可继续操作的对象，不做 workspace 无差别全封锁：在新快照生效时，系统按 `activated_at, id` 保留额度内最早激活对象，将其余标为 over-limit；workspace owner 可通过审计操作归档一个保留对象后再激活另一个，但不能让 active 数超过上限。30 天宽限用于整改和服务升级，不扩大 over-limit 对象的写权限；到期后门禁不变且绝不自动删除。

| 场景 | 结果 |
|---|---|
| 无有效套餐版本/权益快照 | 503/409 fail-closed，进入运营修复 |
| 创作额度不足 | 不调用 provider，显示升级/钱包确认 |
| 钱包兜底未开启/未确认金额 | 不拆分、不调用 provider，返回可恢复的确认动作 |
| Provider 成功但账本结算未知 | 资金保持 reserved、内容禁止交付、禁止重复生成；24 小时自动对账后进入受控人工终结 |
| 存储预占不足 | 不上传、不调用生成模型 |
| 降级后结构权益超额 | 按下列权益类型实施对象级门禁，不删除；进入 30 天整改宽限 |
| 品牌超额 | 超额品牌及其新生成/上传/发布写入阻断；额度内品牌继续工作 |
| 店铺超额 | 超额店铺允许读取远端/已有回执，阻断平台写、发布和新授权；额度内店铺继续工作 |
| 企业主体超额 | 超额主体只读，阻断新品牌/店铺绑定和其名下发布；其他主体不受影响 |
| 存储超额 | Workspace 允许读取/下载/导出并可用既有资产发布；阻断产生持久化对象的上传/生成，不连带阻断服务预约 |
| 创作额度/服务余额不足 | 只阻断对应生成或新预约，不影响已有数据和其他权益 |
| 降级宽限到期仍超额 | 保持上述逐权益门禁；不删除；等待升级/加购或授权逐对象归档 |
| 定制“按需”未解析/费率不唯一 | 不激活订单、不发权益、不调用 provider |
| SLA 日历缺失 | 不承诺 SLA，工单进入配置阻断队列 |
| 平台/模型/支付/存储/scanner 未就绪 | 明确阻断，不回退 fixture 伪造成功 |
| 发布回执 unknown | 对账并人工介入，不重复提交 |
| ERP/定制项目未通过 UAT | 保持关闭，不进入生产凭据 |

## 10. 成功指标

- 100% 对外套餐字段来自已批准套餐版本。
- 100% 订单和账期冻结全量权益及 checksum。
- 品牌、店铺、存储、创作额度并发超限漏放率为 0。
- 权益、模型用量和人民币成本日对账差异率为 0。
- 缺生产配置时误报可用率为 0。
- 平台写入交互确认覆盖率 100%，无人值守写入为 0。
- 服务交付记录完整率 100%，SLA 计时覆盖率 100%。
- 基础/增长首次响应 SLA 月达标率不低于 95%。
- 新付费客户 5 个工作日内完成签约范围验收的比例不低于 90%。
- 套餐权益相关退款/争议率上线三个月内低于 1%。

## 11. 测试与验收门禁

证据等级统一为：E0 静态代码；E1 单元/属性/契约；E2 真 PostgreSQL、RLS、Worker 和服务集成；E3 staging 中通过正式 ChatGPT 插件/桌面浏览器连接真实供应商沙箱或隔离测试租户的端到端证据；E4 生产 canary、真实外部回执及监控。P0 功能至少达到 E3；涉及真实支付、模型、平台写入、对象存储删除和生产 readiness 的对外销售声明必须达到 E4。E0/E1 不得替代“已完成”判断。

1. 套餐版本、权益、额度、服务、SLA、确认票据均有单元和属性/状态机测试。
2. MCP/OpenAPI/Bridge 契约数量、权限、错误码和 UI action 不漂移。
3. PostgreSQL 真库验证 RLS、FORCE RLS、唯一约束、append-only、并发消费和迁移完整性；不得全部依赖内存仓储。
4. 支付、创作额度、模型用量、存储和退款执行全链幂等与对账测试。
5. Worker 多副本、崩溃恢复、lease 过期、重复回调、账期切换和降级测试。
6. ChatGPT 正式插件入口完成安装、读、写确认、超限、错误、恢复和审计验证。
7. Ops 只验收桌面 1440px 工作台，覆盖角色、workspace 切换、深链、刷新、错误和 loading；手机/平板不阻断。
8. 六平台逐能力真实 OAuth/read/write/media/readback canary；未通过的格保持关闭。
9. 五模态保留真实鉴权、request、usage、cost、error；缺配置验证 fail-closed。
10. 托管对象存储/KMS、删除证明、对账、备份恢复和容量证据通过。
11. SLA 使用真实工作日历和可控时钟覆盖暂停、恢复、跨假日、临期与违约。
12. 生产发布前执行类型检查、单元/API、桌面浏览器、容器健康、迁移、release gates、备份恢复和 canary。
13. Ops 配置覆盖草稿、校验、同人审批拒绝、影响预览过期、revision 冲突、定时原子切换、重叠费率、停用和历史版本不变。
14. 双账本覆盖同一 operation 的预占/结算/释放/退款、最早到期扣减、账期切换、钱包 opt-in、真实成本缺失和日对账。
15. 并发品牌/店铺/存储/创作额度不得超卖；降级与宽限必须按第 9 节逐权益对象级门禁验收，回滚和超额处理不得删除业务数据。
16. SLA 覆盖自动回复不计时、首次有效人工响应、等待客户暂停、客户回复恢复、节假日、重开和违约；服务覆盖预约冲突、取消、爽约、完成和人工冲正。
17. 发布确认覆盖 hash 过期、对象/权限/权益漂移、partial/timeout/unknown 和逐项回执；**无有效一次性确认票据**的 Worker 平台写入数必须为 0，持有效票据的确认发布按真实回执计数。
18. 前端覆盖 API timeout/partial/empty/error、只读/越权/跨租户、无硬编码套餐值、键盘路径、焦点恢复和非颜色状态表达。
19. E3 使用键盘和屏幕阅读器实际路径验证 WCAG 2.2 AA，包括对比度、可访问名称、焦点可见/不遮挡、异步播报、错误摘要和字段关联；不得只检查源码字符串。
