# ChatGPT 商家插件与桌面运营后台 QA 报告

日期：2026-09-08
结论：本地工程验收通过；生产上线门禁为 **NO-GO**，不得以本地 fixture 成功替代真实生产证据。

## 验收范围

- ChatGPT 插件入口 → Merchant Bridge/MCP → API → PostgreSQL/RLS/worker 的真实本地链路。
- 桌面商家工作台与桌面运营后台；手机和平板不属于本项目验收范围。
- 平台规则可信边界、OIDC 登录、商业退款治理、迁移链、容器健康与生产发布门禁。

## 本轮修复

1. 商家规则读取隐藏 `manual://` 非可信人工规则；运营侧仍可查看并明确标为未验证，避免插件生成内容引用未取得的平台规则。
2. 迁移 171 恢复退款运行态角色隔离：`merchant_app` 只获得所需读写权限，运营角色不能越权写入租户退款数据。
3. 隔离 Ops OIDC fixture 不再硬编码迁移 169，改为读取 `release-metadata.json` 的期望版本并校验连续迁移链；真实浏览器登录恢复正常。
4. 重新构建六个 worker 镜像，使其与迁移 171 一致；未删除数据库、Redis 或对象数据。
5. 补全退款申请、异人审批、外部退款凭证、点数回收流程；按退款类型强制业务证据，并要求非空 `legal_review_ref`。
6. CI 与 release gate 纳入 migration 171，MCP/Bridge/文档统一为 294/143。
7. 新增运营侧 `knowledge.rule.update`：仅 `rules_admin/reviewer` 可执行，强制乐观锁版本与审计原因，拒绝激活 `manual://` 未验证来源，并支持事件重放恢复；该治理工具不暴露给商家 Bridge。
8. 图片重试补齐商业准入、创意点预留与失败释放；读取任务时会把 worker 的不可重试终态错误投影为失败，避免插件无限轮询。

## 生产上线阻断

`npm run dev:doctor:production` 结果为 39 pass、1 warn、13 fail，按设计返回非零状态。当前仍缺少或未通过：

- 公开 Bridge HTTPS 地址与生产 token、非示例生产配置及 `/readyz` 生产就绪证据。
- 真实支付链路与六个平台 OAuth 授权证据。
- 文本、图片、视频、音频、向量五类模型的真实中转请求、鉴权、usage、cost 和错误证据。
- 托管对象存储/KMS、扫描器签名证据、告警 webhook。
- ChatGPT 真实宿主恢复/重连证据、生产发布证据包和 `productionGate=true`。

因此当前允许继续本地/预发布验收，但不允许宣称生产可上线。只有上述 13 项阻断全部消除并重新跑完发布门禁、桌面浏览器验收和 canary 后，才能给出 GO。
