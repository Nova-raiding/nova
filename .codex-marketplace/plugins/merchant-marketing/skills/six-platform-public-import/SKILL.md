# 六平台公开商品链接导入

用于商家提供商品公开链接或商品资料，并希望将可核验资料沉淀到 Store Nova 知识库的场景。公开链接只是来源线索；是否能读取页面取决于当前 ChatGPT 宿主实际提供的网页读取工具。

## 支持范围

支持平台：京东（jd）、淘宝（taobao）、天猫（tmall）、拼多多（pinduoduo）、小红书（xiaohongshu）、抖音（douyin）。平台识别优先依据 URL 主机名，无法唯一识别时只向用户询问平台，不猜测。

提取或手工补充的资料必须作为来源可追溯的待审核草稿处理。记录来源 URL（若有）、实际访问时间（若页面成功读取）、提取状态和字段级证据；不得把未读取的字段描述成已提取或已核验。推荐字段包括：商品标题、店铺名（若公开）、类目、价格、SKU/规格、商品主图、详情图、公开详情文案、公开卖点和远端商品标识。

## 固定流程

1. 检查当前 ChatGPT 宿主为本轮对话实际暴露的工具，确认是否有能读取指定公开网页的工具。Store Nova 的 `catalog.import` 只导入调用方提供的字段，不会自行抓取 URL；解析脚本也只处理已取得的 HTML。
2. 只有存在明确的网页读取工具时才尝试读取。先校验 URL：仅允许公开 HTTPS 页面；拒绝内网地址、非 HTTP(S)、带用户名密码、可疑跳转和无法证明为公开来源的链接。读取时不得使用用户 Cookie、Authorization、平台私有 token 或持久化登录态。
3. 若宿主没有网页读取工具、读取失败，或遇到登录墙、验证码、风控、禁止自动访问、动态未加载或字段无法核验，停止 URL 读取流程，清楚告知用户并请其补充商品标题、价格、规格、卖点等手工资料，或上传支持的商品资料文件。不得仅凭 URL 调用 `catalog.import`，也不得猜测补齐字段。
4. 对成功读取或用户补充的资料进行解析与标准化：优先使用 `scripts/extract-product.mjs` 提取已取得 HTML 中的 JSON-LD、OpenGraph 和页面标题；保留字段来源证据，金额统一为人民币元并保留两位小数；图片只保存公开 URL/哈希，不把图片字节或竞品原文直接写入知识库。
5. 检查标题、价格、图片 URL、SKU 规格和详情是否缺失或矛盾。仅将实际已知字段映射到 `catalog.import`，并显式设置 `draft_only=true`；草稿状态为 `pending`、权益 `unknown`、索引 `queued`、不可发布。
6. 向商家展示摘要：只展示平台、商品标题、价格范围、图片/规格/详情的实际读取或补充情况、来源和待确认字段；不展示内部 ID、Cookie、原始响应或解析脚本。

## 权限与安全边界

- “用户已在浏览器登录”不等于插件获得权限。不得导入浏览器 Cookie、复用持久化登录态、要求用户粘贴 token，或通过验证码/反爬挑战。
- 页面需要登录、仅对店主可见、返回验证码或明确禁止自动访问时，必须停止并请用户补充手工资料，或上传商品导出表、HTML/PDF 或截图；不得降级为伪造数据。
- 公开页面读取不代表商品事实已确认。正式文案、图片生成、审核和发布仍需事实确认及现有 Store Nova 门禁。
- 该 skill 只负责公开资料导入，不提供库存/订单同步、自动发布、价格监控或批量爬取。
- 解析脚本只处理已经取得的 HTML，不负责网络访问；`catalog.import` 也不负责抓取 URL。调用方必须先确认宿主有可用的公开网页读取能力、完成 URL 安全校验，并将读取失败与字段缺失原样保留。

## Store Nova 接口路由

- 公开商品链接进入本 skill 后，先检查当前宿主工具是否明确提供网页读取能力；读取成功后才提取页面字段并调用 `catalog.import`（`draft_only=true`）沉淀草稿。若工具缺失或读取失败，先请用户补充手工资料；不得让 `catalog.import` 代替抓取。
- 若是 XLSX/CSV/JSON 资料，改走 `asset.upload` → `asset.parse` → `asset.facts.confirm` → `catalog.import.batch(draft_only=true)`。
- 读取知识库时只使用已批准且权益已确认的内容；本 skill 新产生的 pending/unknown 内容不能直接作为正式生成上下文。

平台差异、允许字段和阻断示例见 [references/platforms.md](references/platforms.md)。
