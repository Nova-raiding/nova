# 电商商品图片工作流

本技能负责识别交付物、整理创意方向并路由到 Store Nova 商家工作流，不是独立图片生成器。只有当前插件会话实际提供相应 MCP 工具且服务端允许时，才能开始媒体任务。

## 先确定交付物

- **分析、诊断或创意策划**：通过 `merchant-marketing` 核对当前工作区的商品事实和可用素材，再给出文字建议。区分已确认事实、视觉观察和待核验项；不把图片外观推断成材质、功能、认证或性能事实。
- **一张主图、Banner 或详情图**：确认商品/SKU、用途、用户指定的构图方向与文案。只有用户明确要求生成或修改图片时，才检查当前 MCP 工具清单并进入 `merchant-marketing` 图片流程。
- **一组主图或详情套图**：先按买家决策顺序给出逐张方案，例如主视觉、已证实卖点、细节/参数、真实使用场景和顾虑解答。每张图只承担一个主要沟通任务。用户确认整组方案后，按工具实际支持的方式逐张提交；不假定有批量能力。
- **视频脚本或分镜**：由 `merchant-marketing` 路由到已安装的视频脚本/分镜技能。交付内容是文本候选，不是视频成片。
- **视频成片**：先确认当前 MCP 清单包含成片请求和查询工具；再由 `merchant-marketing` 检查素材、商品事实、权益、relay、费用、审计与归档扫描门禁。工具或门禁缺失时说明阻断，不用脚本、提示词或排队状态替代成片。

用户只说“做电商图”“设计一下”且无法判断要分析、方案还是图片时，只问一个问题确认交付物。不要展示会让用户误以为独立分支已启用的菜单。

## 商品真实性与套图规划

规划或复核时，使用当前工作区已确认资料和用户提供的参考，锁定商品外形、比例、颜色、标签、Logo、配件及 SKU 差异。只改变已确认方案允许变化的背景、光线、角度或构图。不同 SKU 的身份和素材分开处理。

按购买决策规划，不为凑图数生成：

1. 主视觉清楚展示商品和一个核心用途。
2. 卖点图只表达有来源支持的事实。
3. 细节图放大可核验结构、规格或适配范围。
4. 场景图使用真实且已确认的用途。
5. 顾虑解答图只回答有证据的问题。
6. 收口图只呈现已核实的能力和当前渠道允许的信息。

上述顺序是策划参考，不是固定屏数或平台合规保证。平台规则、版位规格、价格、评价、认证及促销必须来自当前可核验来源；来源缺失或过期时标为待核验，不用模型记忆补齐。

## Store Nova 执行边界

- 每次实际媒体操作前检查当前会话 `tools/list` 和工具参数；技能文件存在不代表工具已部署。
- 实际上传、生成、查询和交付只通过 `merchant-marketing` 当前 MCP 与服务端中转；服从真实工作区身份、素材扫描和权益、用户确认、成本、权限、审计、结算及归档门禁。
- 不调用宿主图片工具、第三方 provider/API/CLI 或本地生成脚本；不要求用户提供第三方模型密钥。
- 不把提示词、静态草图、上传原图、任务 ID、排队状态或模型自述说成已生成成品。图片只有在工具返回真实附件后才可称为生成候选；视频只有在 provider 成功结果和可用成片引用返回后才可称为已渲染。
- 工具失败、状态未知、费用结算失败、扫描/归档证据缺失时停止并说明实际阻断，不自动创建重复任务。
- 候选图仍是未批准、未发布内容；人工观察不等于机器质检或平台审核通过。
