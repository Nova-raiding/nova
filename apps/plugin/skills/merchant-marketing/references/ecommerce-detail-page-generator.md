# 大麦插件电商详情图规划适配

本参考来自开源 `ecommerce-detail-page-generator` 的商品事实、平台适配和模块校验思路，已适配大麦插件的 MCP、创意点、租户权限、人工审核和发布门禁。

## 插件内调用边界

- 这份参考只负责商品分析、购买逻辑、详情页模块规划和校验字段，不创建第二套图片生成入口。
- 正式图片必须通过 `catalog.image.generate` 的服务端模型中转；不得调用宿主 `image_gen`、外部网关或本地脚本绕过创意点、鉴权和审计。
- 本地排版、长图、切片和 manifest 只能作为方案预览或离线验证；正式交付仍以 MCP 返回的候选、真实渲染证据、人工审阅、内容审核和发布门禁为准。
- 平台规则缺失、过期或标记为需要商家后台确认时，保留阻断和 `seller_backend_confirmation` 状态，不能把工作画布尺寸说成平台已批准规格。

## 标准计划数据

把完整计划组织为以下结构，再交给当前任务的制作方案/视觉候选流程：

```json
{
  "product": {
    "name": "用户确认名称",
    "category": "图片可见或用户确认品类",
    "facts": [
      {"key": "参数名", "value": "参数值", "source": "user|visible|unconfirmed", "publish": true}
    ],
    "unknowns": ["待确认信息"]
  },
  "buyer_logic": {
    "need": "买家为什么需要它",
    "first_confirmation": "买家第一眼要确认什么",
    "pre_order_concerns": ["下单前顾虑"],
    "proof_requirements": ["必须由画面证明的内容"]
  },
  "modules": [
    {
      "role": "hero|parameters|detail|scene|stability|closing",
      "concern": "这一张只解决的顾虑",
      "headline": "已确认事实组成的标题",
      "visual": "画面内容和产品摆放",
      "allowed_copy": ["允许出现的文字"],
      "forbidden_copy": ["禁止出现的文字或未确认事实"],
      "evidence": ["素材或参数来源"],
      "acceptance": ["验收检查点"]
    }
  ]
}
```

事实来源只允许 `user` 或 `visible` 进入发布文案和图片文字；`unconfirmed` 只能进入待确认和阻断提示。产品照片无法证明的隐藏结构、材质、尺寸、容量、性能、认证、兼容性、销量、评价和优惠不得补写。

## 六类模块到大麦流程的映射

| 视觉角色 | 主要回答 | 大麦交付路径 |
| --- | --- | --- |
| 首屏利益图 | 产品是什么、核心使用收益是什么 | 视觉方向 → 方案确认 → `catalog.image.generate` |
| 核心参数图 | 哪些参数可以核对 | 事实快照 → 方案确认 → 候选图审阅 |
| 结构细节图 | 买家会放大追问哪个部件 | 原图/可见结构 → 保真检查 → 候选图审阅 |
| 使用场景图 | 买家如何在一个真实任务中使用 | 场景方案 → 候选生成 → 人工审阅 |
| 稳定体验图 | 连接、按键、通话、麦克风、续航等日常顾虑 | 仅使用已确认能力 → 候选生成 → 规则审核 |
| 汇总收口图 | 已证明的能力、规格和适用范围 | 事实与平台规则复核 → 发布预览 |

每张图只保留一个主要顾虑，最多三个已确认证明点。智能眼镜等 AI 硬件优先检查镜头、麦克风、按键、接口、佩戴位置和连接场景；具体像素、视角、芯片、协议、容量和续航必须有用户或资料证据。

## 验收

- 计划在生成前已经展示，且没有把草稿、模型偏好或候选数量说成交付。
- 每个 claim 都能追溯到商品事实来源；无来源就进入 `unknowns` 或 `forbidden_copy`。
- 商品形状、颜色、Logo、按键、接口和可见配件没有跨模块漂移。
- 相邻模块不重复同一构图；场景图表达真实任务，不只是更换背景。
- 文字安全区、画布尺寸、切片和平台规格以当前平台证据为准。
- 候选图标注“未批准/未发布”；没有真实性 gate、人工审阅、内容审核和哈希校验，不进入绿色完成态。
