## 本轮新增并验证的闭环

- 平台身份中心持久化全局身份、认证会话与风险策略；支持封禁/解封、风险转换、会话撤销、revision 冲突和审计。
- 模型账务新增持久结算状态机、批量重试、人工重试/豁免/转人工与对账接口；运行态返回 `completed` 且未结算记录为 0。
- API/Worker 改用 `merchant_app` 非超级用户数据库角色；真实事务 RLS 探针在 workspace A 可见、切换 workspace B 后为 0 行。
- Ops 首屏请求并发限制为 8，限流按 workspace + actor + surface 分桶；复测不再出现 429，交互请求不被后台加载饿死。
- 修复 E2E 共享匿名限流桶污染：纵向套件隔离非目标限流副作用，限流本身继续由独立 security E2E 和分布式 smoke 验证。
- 修复 API 模式商品加载失败时展示可操作 fixture 的 P0；失败、空数据和成功状态严格分离。
- 店铺名称与账号贯穿商品、任务、事实、发布确认与驳回修正；缺失或错配 fail-closed。
- 修复 Worker 在 `OPS_AUTH_MODE=oidc` 与内部 Host 下误入 OIDC 的 P0；Bearer/HMAC 正反矩阵通过。
- 工作区状态读取纳入 PostgreSQL 事务；停用、API 重启、阻断、恢复的运行态链路通过。
- Merchant 五个一级页面和任务均具备稳定 URL；刷新、前进/后退和商品搜索 query 可恢复，任务只从服务端权威身份重建。
- 新任务创建在客户端并发与服务端重放两层幂等；URL 刷新不重复创建，复用键改变意图返回冲突。
- Merchant 原生 `prompt/confirm/alert` 已归零；充值、撤销、导入、任务组、主图结果、素材权益/事实和标题修改均使用带校验与失败恢复的应用内对话框。
- 素材列表不再与品牌档案和存储 health 同生共死；辅助接口失败保留素材元数据并提供独立重试。
- 商品列表已实现真实分页与筛选复位，详情预览规格按钮提供明确的选中状态；只读设置入口更名为工作区信息。
- 宿主 Codex 通过同一中转站真实返回 `RELAY_OK`；业务文本、图片、图片编辑、OCR、视频五模态 canary 全部获得 HTTP 200、provider/task ID、usage 和版本化成本快照。图片改用实测可用的 `qwen-image-3.0`；视频任务状态最终为 `succeeded` 并返回 HTTPS 成片，创建与状态回读合同已闭环。

## 已发现并修复

### ISSUE-001（高）UI 容器重建 API 后持续 502

Nginx 在启动时缓存了旧 API 容器 IP。改为运行时 DNS 解析 `merchant-api`，API 容器替换后无需重启 UI。修复后平台账号、能力证据和健康接口均恢复 200。

### ISSUE-002（高）首页运营指标 HTTP 500

两条历史内容版本使用旧 schema：模块缺少 `factSourceIds`，视觉 Brief 缺少数组及必填文本。审核读取直接访问 `.length` 导致异常，并使 `workspace.metrics` 整体失败。现在读取时只做兼容归一化、不改写历史快照，并输出 `MISSING_SOURCE`、`VISUAL_BRIEF_INCOMPLETE`、`TECHNICAL_SCHEMA_INVALID`。两条审核和指标接口均恢复 200。

### ISSUE-003（高）本地生产身份门禁在 API 重启后使 UI 401

Compose 仍使用旧 token 数组格式，且 `ws_demo` 没有 owner 成员。现改为带 `actor_id`/roles 的 token grant，并由仅限本地 Compose 的幂等 SQL 初始化 `actor_demo` owner。

### ISSUE-004（中）素材图片原生请求缺少工作区头

`<img src>` 无法附加 `X-Workspace-Id`，导致素材预览 403。现由前端使用带租户头的 authenticated fetch 读取 Blob；对象存储未配置时不再自动发起必失败请求，并明确禁用正文读取。

### ISSUE-005（中）Ops Console 本地运行被 CORS 全面阻断

本地 Vite 直接跨域请求 API，首次测试 52 个 MCP 请求均被浏览器拦截。现提供 `/api` 同源开发代理，保持生产 API 的 CORS 收紧策略。复测四页真实数据正常。

### ISSUE-006（高）Ops 全局加载存在旧请求覆盖与失败清空

并发页面加载会产生大量取消请求，旧响应可能晚到覆盖新状态，可选接口短暂失败还会把已有数据清空。现使用 latest-request-wins 协调器，仅最新请求可提交；可选接口失败保留上次成功数据，真实空数组仍可正常清空。定向 20/20 与完整浏览器遍历通过。

### ISSUE-007（高）辅助商品身份失败遮蔽成功任务列表

任务接口成功但商品身份接口失败时，页面曾把成功任务一起隐藏。现两者独立加载、独立报错和重试；任务保持可浏览，身份补齐前恢复动作安全禁用，重试成功后补齐商品/店铺名称并恢复操作。Merchant 数据安全回归 14/14 通过。

### ISSUE-008（高）Kubernetes 镜像门禁可被 YAML 文本诱饵绕过

原 `awk` 扫描无法区分 ConfigMap 与工作负载，也可能漏掉引号键和 initContainer。现改用 Psych YAML AST，结构化遍历 PodSpec 的 containers、initContainers、ephemeralContainers；未知 kind、重复键、alias、畸形 YAML 与可变标签全部 fail-closed。发布脚本定向 27/27 通过。

### ISSUE-009（高）规则与类目 API 失败仍混入演示数据

配置真实 API 后，规则或类目失败/空响应曾继续展示安全演示项，可能让商家把演示证据误当成生产数据。现严格区分加载、失败、真实空数据、真实数据和离线演示五种状态；两个接口独立报错、独立重试，API 模式绝不回退 fixture。新增两条浏览器负向场景通过。

### ISSUE-010（高）工作区目录无界并发耗尽数据库连接池

平台运营目录对约百个工作区同时发起五类仓储读取，真实浏览器遍历出现一次 `ops.workspaces.list` 500。现按工作区有序限流为最多 2 个并行；8 个并发真实请求全部返回 200，约 1.28 秒，随后完整 Ops 与 42 项浏览器回归均通过。

### ISSUE-011（严重）敏感店铺与账单方法缺少服务端角色门禁

前端虽然隐藏了部分按钮，但普通活跃成员仍可直接调用 `platform.revoke`，`billing.export` 也未限制财务角色。现服务端在资源查询和副作用前统一校验：店铺别名/撤销仅 owner、merchant admin、platform ops；账单导出仅 owner、merchant admin、finance、platform ops。低权限、跨工作区、header/body 不一致和授权角色安全矩阵 95/95 通过。

### ISSUE-012（严重）API 任务事实区混入客户端演示证据

API 返回非服装 draft 任务时，页面曾显示固定 A/B/C 方向、防晒规则和虚假完成进度。现 API 模式只展示服务端方向、规则版本和 task state；缺失或失败显示明确空态/重试，只有无 API 的离线模式保留带“演示”标识的 fixture。新增非服装、非 A/B/C 正反浏览器场景，完整 Merchant 数据安全套件 14/14 通过。

### ISSUE-011（中）运营修正版要求手填原始 JSON

发布修正版原使用 `window.prompt`，无法提供字段错误、取消保护和失败聚焦。现改为结构化 Ant Design Modal/Form；非法 JSON、数组、`null`、空对象、空原因和取消均不发请求，请求失败保留表单并聚焦错误，成功后才刷新。

### ISSUE-013（高）发布后台刷新失败隐藏上次成功数据

发布中心 5 秒轮询短暂失败时曾把成功任务与回执一起隐藏。现首次失败仍阻断，后台失败只展示可恢复警告并保留上次成功数据；重试恢复后原子更新列表并清除警告，API 地址变化会清空旧来源以防跨环境串数据。

### ISSUE-014（高）数据删除审批缺少具体理由与动作隔离

审批/取消曾使用硬编码理由且无逐动作 loading。现使用结构化 Modal，原因至少 4 字并原样写入 RPC 审计；按申请和动作防双击，500 保留输入可重试，审批与取消 loading 相互隔离。浏览器 3/3 通过。

### ISSUE-015（高）批量发布只能查看，无法安全暂停或恢复

现支持暂停、恢复和失败项重试。暂停明确不撤回已入平台队列项目；恢复不会盲重试；失败项必须提交 1–50 条新的内容版本、确认哈希、远端快照哈希和幂等键，缺字段不发请求。500 保留输入，双击只提交一次。

### ISSUE-016（高）任务辅助 API 失败被伪装成空数据

任务恢复曾把 feedback/timeline 请求失败吞成空数组，用户无法区分“没有记录”和“读取失败”。现两类数据独立保存错误状态和上次成功记录，失败显示可恢复告警，重试成功后原子更新并清除错误；专项 Chrome 回归覆盖两个接口先失败后独立恢复。

### ISSUE-017（高）审核风险接受依赖原生 prompt

内容审核的“带理由接受”曾使用原生 prompt，无法做字段级校验，服务端失败后输入也会丢失。现改为结构化弹窗：原因至少 4 个字符，提交中锁定；500 保留原输入和弹窗，成功后才关闭并展示原样审计理由。专项 Chrome 回归覆盖零请求校验、失败和安全重试。

### ISSUE-018（高）Merchant 刷新丢失页面与任务上下文

现以 History API 提供五页 canonical URL、query 保留、前进/后退和旧 hash 兼容；任务 URL 只携带稳定任务 ID，刷新后从任务与商品 API 恢复权威店铺身份，伪造 query 不会覆盖服务端事实。

### ISSUE-019（高）新任务并发与刷新可能重复创建

新任务地址携带一次性 intent，客户端合并并发请求，服务端按工作区与幂等键返回同一任务；同键不同意图返回 409。任务创建成功后 URL 原地升级为稳定任务地址，且不会重启当前工作流。

## Design Critique

| Nielsen 启发式 | 评分（1–5） | 证据 |
|---|---:|---|
| 系统状态可见 | 4 | Merchant 展示健康、钱包、同步与能力门禁；Ops 展示加载和刷新状态，但跨区域请求失败仍以全局提示为主。 |
| 符合用户心智 | 4 | 商家端使用商品、店铺、事实、发布语言；Ops 仍直接展示 `ws_*`、英文状态与角色标识。 |
| 用户控制与恢复 | 4 | 失败态提供重试，危险操作有确认；部分长表单尚无撤销或草稿恢复。 |
| 一致性与标准 | 4 | 两端导航、卡片、状态标签和表格模式基本一致；Merchant 与 Ops 的视觉系统仍明显分裂。 |
| 错误预防 | 5 | 店铺身份错配、余额不足、未配置模型、发布/退款风险均 fail-closed。 |
| 识别优于记忆 | 4 | 关键动作和状态可见；部分运营动作仍要求输入 JSON、证据引用或原始 ID。 |
| 灵活与高效 | 4 | 搜索、筛选、分页、一级深链和批量发布治理可用；Ops 仍缺工单和完整导出闭环。 |
| 美观与克制 | 4 | Merchant 层级和留白成熟；Ops 首屏角色条和长工作区表信息密度偏高。 |
| 错误诊断与恢复 | 4 | 错误提示区分失败与空数据并提供重试；外部能力阻断原因较多，仍可进一步按行动分组。 |
| 帮助与文档 | 3 | Merchant 有帮助与诊断入口；Ops 缺少与当前错误/配置项直接关联的运行手册入口。 |

视觉层级前三项：Merchant 主任务 CTA 与门禁状态清晰；Ops 原始身份配置占据首屏、抢占业务摘要注意力；Ops 长表格应把工作区名称/商家作为主信息，把原始 ID 降为次要可复制字段。字体和颜色当前未发现阻断上线的可读性问题，但 Ops 的英文状态与等宽原始标识削弱了面向运营人员的产品感。

| 优先级 | 建议 |
|---|---|
| 上线前 | 保持所有真实外部能力 fail-closed；任何错误必须提供恢复动作并通过 `role="alert"` 公告。 |
| 下一迭代 | 补齐 Ops 工单和完整导出；把剩余原始 JSON/ID 输入改为结构化表单与选择器。 |
| 打磨 | 统一两端设计 token；降低 Ops 顶部身份配置视觉权重，补充运行手册深链。 |

## 当前环境无法完成的外部能力

这些是健康接口明确返回的部署门禁，不计为“已通过”：

- 六个平台官方连接器、真实 OAuth/read/write/canary 尚未配置。
- 业务模型中转与宿主 Codex 已通过安全启动入口恢复，本地五模态真实回执和成本证据已完成；仍缺托管生产 Secret 与正式生产 release 签署。
- S3 兼容对象存储、生命周期和版本化尚未配置；页面已明确显示不可读取正文。
- 插件钱包余额为 ¥0.00，生成、图片、视频和发布写入被正确阻断。
- 生产写入关闭，因此未执行撤销授权、真实发布、退款、成员变更、商业配置保存等有外部副作用的操作。

要把上述能力也标记为通过，必须提供可测试的沙箱平台账号、模型 Relay、对象存储、测试钱包资金和生产证据配置。
