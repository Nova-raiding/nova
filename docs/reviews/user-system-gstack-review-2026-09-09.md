# 用户系统 PM / gstack 评审

## 结论

用户系统的主链路已经覆盖身份、工作区、角色权限、钱包、扣款、任务、账单、订单、店铺授权和审计。当前最重要的产品规则是：身份是入口，工作区是业务数据边界，权限是服务端 capability，商业状态是扣款和任务执行的准入条件。

## 多视角评审

| 视角 | 结论 | 已落实动作 |
|---|---|---|
| 用户 | 用户需要知道“我是谁、在哪个工作区、能做什么、余额和任务还能用多少” | 两个后台增加账号状态、工作区、会话与业务归属展示 |
| 产品 | 公共注册会产生没有租户和账务归属的孤儿账号 | 商家采用邀请接受，平台账号预配，不开放无审批注册 |
| 工程 | 前端展示不能代替 API、RLS 和账务事实 | `ops.session`、身份生命周期、权限投影、RLS 和账务门禁保持服务端权威 |
| 风险 | 身份停用、工作区停用、余额未知、支付未对账、模型成本缺失都必须阻断 | UI 显示未确认/阻断态，不把空值当成成功或零余额 |
| 运营 | 用户治理必须能从主体追到账单和流水 | 用户详情展示商业快照；财务检索支持按 actor 搜索订单和钱包流水 |
| 视觉 | 桌面运营台适合密度较高的信息布局，但长表必须有明确横向滚动和详情入口 | 保留表格滚动容器，详情抽屉分组展示身份、商业、会话、角色和审计 |

## 评审发现与处理

### F-001：用户详情只有商业汇总，缺少明确的业务分类

**影响：中高。** 平台运营可以看到套餐和余额，但不容易确认任务、扣款和账单是否属于同一工作区。

**处理：已修复。** 用户详情新增“商业、钱包与任务状态”分区，展示套餐、订阅/权益、任务用量、钱包余额、扣款与账单核对状态。缺失数据显示“未确认”。

### F-002：财务检索无法按用户主体定位流水

**影响：高。** 身份治理与财务对账之间缺少可追踪键。

**处理：已修复。** 充值订单、钱包流水、订阅订单的安全检索文本加入创建者/操作主体字段，保留权限和 RLS；新增回归测试防止 actor 归因丢失。

### F-003：未登录账号面板可能收到 HTML 登录页

**影响：中。** 前端 JSON 解析失败时会显示为“服务不可用”，恢复动作不准确。

**处理：已修复。** 本地 OIDC 网关对 `/auth/session` 返回结构化 `401 UNAUTHENTICATED`。

### F-004：用户详情接口没有补齐商业快照

**影响：高。** 用户目录列表已经返回套餐、任务和钱包状态，但详情抽屉调用 `ops.user.detail` 时成员关系没有携带同一份商业数据，真实数据下会把详情显示成“未确认”。

**处理：已修复。** `ops.user.detail` 现在按成员工作区加载商业快照，并返回套餐、订阅、任务用量、剩余任务和钱包余额；服务端回归测试覆盖列表与详情的一致性。

### F-005：订阅状态容易被误读为扣款完成

**影响：中高。** `subscriptionStatus=active` 只说明订阅权益有效，不能单独证明钱包余额、支付回调和账单对账已经通过。

**处理：已修复。** 详情页将状态改为“订阅有效，账务仍需门禁核验”，使用中性色，不显示绿色完成态；只有缺失数据才显示“未取得账务快照”，继续保持 fail-closed。

### F-006：商家会话故障被显示为“待配置”

**影响：中。** `/auth/session` 在 OIDC 未配置、网关异常或网络失败时，账号面板原先把状态显示成“待配置”，无法区分未登录和身份服务故障。

**处理：已修复。** 未登录仍显示“未登录”；会话接口异常显示“会话服务不可用”，并保留登录/接受邀请入口，避免把服务故障误导成用户配置问题。

### F-007：可安装插件镜像落后于源包

**影响：高。** Bridge 工具数和 `release-metadata.json` 已经是 144 个并通过校验，但 marketplace 镜像的入口 Skill 与源包不一致，安装后可能拿到旧的使用和安全说明。

**处理：已修复。** 同步 `apps/plugin` 到 `.codex-marketplace` 的 Skill 镜像，并通过插件镜像、Bridge 发现、release metadata 和 release manifest 门禁。

## 仍然是上线门禁

本地 OIDC 和 Postgres 隔离环境通过不等于生产身份源已接通。正式交付仍需真实 HTTPS IdP、独立 admin/ops/mcp OAuth client、refresh token、Redis state/nonce、支付回调和 ChatGPT MCP OAuth 实测证据。任何一项缺失时，平台保持未验证，不显示绿色完成态。

### F-008：商家后台异常任务数据导致滚动后白屏

**影响：高。** 任务列表排序直接调用 `createdAt.localeCompare`，异常或历史任务缺少时间字段时，浏览器在渲染列表阶段抛出异常，表现为滚动后页面变白。

**处理：已修复。** 排序对缺失时间字段做安全归一化；新增回归测试覆盖缺失 `createdAt` 的任务，并通过商家桌面浏览器全量回归 22/22，运营台滚动稳定性回归 10/10。

### F-009：`automation.scan` 被错误归类为纯只读能力

**影响：高。** 扫描实现会 upsert 运营告警并发送通知，却被商业门禁和插件说明标记为只读，可能让未完成店铺绑定的工作区触发运营侧写入。

**处理：已修复。** 从只读方法集合移除 `automation.scan`，在扫描入口先执行真实店铺边界，再执行商业访问判断；插件和 MCP 契约改为明确说明“会记录风险告警”。新增生产 onboarding 回归，确认无店铺时返回 `STORE_ONBOARDING_REQUIRED`。

**新增验收：** 安全、Feature Gap、Bridge、插件镜像回归 232/232；发布门禁 569/569；商家浏览器 22/22；运营浏览器 10/10。
