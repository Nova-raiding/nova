# 商品主图与详情长图视觉生成方案（2026-09）

## 现状与根因

此前本地 fixture 在没有图片中转时会读取 `artifacts/merchant-product-main-v2.webp` / `v3.webp`。这会把原始商品图当成“候选设计”返回，尤其当调用方误传 `mode=create` 且同时带有原图时，用户看到的是原图而不是重新构图。详情长图虽然允许 `1024x3072`/`1024x4096`，但提示词只有泛化的“多个章节”，模型容易输出一张大画布或把方卡片机械拼接，中文营销字也无法稳定渲染。

## 参考方案与取舍

- [ComfyUI E-Commerce Workflows](https://github.com/xiaoqahax-ui/comfyui-ecommerce-workflows) 提供去背、ControlNet/IP-Adapter 保真、详情页复合排版和批处理的流程，可作为未来自托管 provider 的节点参考；其模型和节点许可证仍需逐项审查。
- [codexQIYU-image-workflow](https://github.com/QIYU-JACKMAN/codexQIYU-image-workflow) 将商品事实、提示词优化、客户确认、逐图质检和失败续跑串成生产流程，适合借鉴任务编排和审阅门禁。
- [ComfyUI-productfix](https://github.com/MiddleKD/ComfyUI-productfix) 专注保留电商商品文字、Logo 和细节，适合作为真实性检查/局部编辑的可选 provider 能力。

本项目不直接嵌入这些仓库，也不绕过 Merchant MCP。生产图片始终经配置的模型中转、真实用量与成本回执、对象归档、安全扫描、真实性检查和人工选择。开源工作流只能作为中转服务的实现参考；缺少中转配置时必须失败关闭。

## 同类视觉样本（淘宝/天猫轻户外防晒衣）

当前夹具商品是淘宝生态的轻户外防晒外套，但没有商家提供可核验的具体竞品链接，因此本节只记录公开行业样本，不把它们当作品牌竞品或商品事实。公开的[淘宝防晒衣详情页模板样本](https://www.tuwangwang.com/89456)呈现了较稳定的购买信息顺序：首屏利益点（轻薄/防晒）→ 面料与功能证据 → 户外/通勤场景 → 结构细节（帽子、拉链、下摆）→ 参数与尺码表。它适合作为“信息编排假设”，但其中的 UPF、阻隔率、面料成分等数字不能迁移到本商品。

因此本项目的差异化策略是：借鉴“先收益、后证据、再规格”的节奏，但将每个数字和功效替换为本商品已确认事实；主图只做商品识别和轮廓优势，副图承载 1 个场景或 1 个证据，详情长图用连续章节解释购买顾虑，不把多个促销贴纸堆在首屏。正式任务仍必须由商家补充 3–5 个同平台真实商品页，记录 URL、抓取时间和结构化观察后才允许进入图片 brief。

竞品预检建议以以下矩阵落盘，便于模型只消费“结构”而不是竞品内容：

| 观察维度 | 竞品记录 | 本项目决策 |
| --- | --- | --- |
| 首图构图/主体占比 | 白底、场景或混合；主体相对画布比例 | 淘宝/天猫主图商品优先，主体完整；场景表达移到副图 |
| 首屏文案密度 | 是否有利益点、价格或活动角标 | 只注入已确认 headline/price/promotion；最多一个 CTA |
| 证据呈现 | 面料、工艺、测试、细节放大或使用步骤 | 每个卖点绑定一个可追溯证据，不用竞品数字 |
| 详情章节 | 利益点→场景→细节→规格→售后等顺序 | 固定 8 章连续叙事，禁止方卡片纵向拼接 |
| 差异化空位 | 同质化色彩、角标、口号和场景 | 只改变可借鉴的构图/节奏；用本品牌色、真实卖点和 SKU 边界形成识别 |

平台信息也要保持可追溯：淘宝开放平台的素材格式枚举明确区分了主图/副图、详情页图、创意图、促销词、优惠券和价格等素材类型（见[官方文档](https://developer.alibaba.com/docs/api.htm?apiId=68769)），所以系统把营销标签作为独立、可审计字段，而不是让模型自由编造文字。抖音官方学习中心也说明主图视频封面会出现在商品详情主图位置，并强调视频用于补充决策信息（见[主图视频创建指南](https://school.jinritemai.com/doudian/wap/article/113410?from=dibujiedu_02&from_school=1&should_full_screen=1&should_hide_bottom_nav=1)）；这支持将“首图/封面信息密度”和“详情证据链”分开设计。

## 已落地的生成契约

1. 带有原图引用的任务在没有图片中转时直接返回 `IMAGE_GENERATION_NOT_CONFIGURED`，不再读取静态 fixture 资产伪装成设计结果。
2. 视觉 brief 冻结平台规则、营销标签、输出变体和详情章节。营销标签只来自已确认标题、副标题、价格/促销快照和 CTA；未确认的销量、折扣、功效、认证和排名永远不会进入提示词。
3. `1024x3072`/`1024x4096` 长图固定采用 8 章购买逻辑：价值主张、痛点场景、核心卖点、使用流程、细节证据、参数规格、SKU/套餐边界、信任与行动。每章一个购买顾虑，同一网格、字体、色板和光影连续，禁止方卡片机械纵向拼接。
4. 主图遵循平台纯净度优先：商品主体大而完整，营销信息放在详情长图和副图；营销信息若要进入主图，必须由平台规则快照明确允许，且仍需人工审阅。

## 平台适配基线

平台规格会按类目和活动变化，生成前使用服务端已生效规则，发布前以商家后台最终校验为准。默认基线为：主图 1:1、主体约占 70–85%、四周保留至少 6% 安全区；详情长图 750/1024 宽度按平台规则映射，长画布只用于连续章节，不以尺寸本身宣称平台已批准。京东、淘宝等搜索主图优先保持商品清晰和低文字密度；抖音/小红书的 3:4 内容电商变体可以承载一处利益点，但不得遮挡商品。

## 验收门禁

- 技术：实际像素等于请求尺寸；PNG/JPEG/WebP 签名、大小和 MIME 一致；长图不是多个正方形结果的机械拼接。
- 视觉：120px 缩略图仍能识别商品；主体完整、颜色/Logo/SKU 不漂移；每章有明确结论、统一网格和可读安全区。
- 事实：每个价格、促销、参数和卖点可回溯到冻结商品事实或促销快照；缺证据即省略或阻断。
- 运营：候选标记“未批准/未发布”，经安全扫描、真实性检查、人工审阅、内容审核和发布确认后才可进入平台写入。

## 后续迭代

接入真实中转后，优先增加 mask-guided 商品主体锁定、OCR/Logo 检查、长图章节切片预览和平台规则版本化快照。自托管 ComfyUI 仅在 GPU、模型许可证、成本回执和生产 canary 证据齐备后启用。
