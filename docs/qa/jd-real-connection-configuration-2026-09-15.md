# 京东真实连接配置修复

当前插件返回的是模拟授权，不代表京东店铺授权成功。主 API 和副本均启用 CONNECTOR_FIXTURE_MODE=true，均无 JD 配置；本工作区 .env、进程和 macOS 用户会话也未提供京东应用凭据或 Vault 配置。

新增 infra/local/docker-compose.jd-oauth.yml，作为本地 Compose 的明确官方授权覆盖文件。两个 API 副本同时关闭模拟连接，要求应用凭据、应用批准的授权/换票/API 地址、注册的 HTTPS 回调和 Vault。不会提供猜测值，不在仓库保存密钥，也不启用商品发布。

安全配置就绪后，由部署人员将覆盖文件放在 docker-compose.yml 之后执行配置渲染和 API 更新。不要打印完整渲染配置，其中含注入的密钥。此覆盖会关闭全部平台的 fixture，因此其他未配置平台会保持阻断。只改变授权入口，不证明商品读取、媒体上传或发布已通过生产验收。

必须使用与京东应用类型一致的官方 OAuth 协议和权限；不要混用京东健康、物流或不同开放平台的接口。当前运行镜像还须更新到包含 OAuth 独立准入实现的版本。插件升级不能代替 API 更新。

最终验收：插件给出真实京东官方授权地址（非 simulated），商家在京东完成同意；回调校验一次性 state、工作区、平台和回调地址；凭据安全写入 Vault；主副本均返回非 fixture 店铺状态；按明确店铺范围执行经审批的只读验证。任何一项缺失都不得报告已连接。当前未重启容器、未修改业务数据、未完成真实授权。

验证：Compose 配置门禁、连接器配置、HTTP OAuth 和 Vault 共 4 文件 74 项测试通过；连接器 TypeScript 构建通过。测试仅证明代码与配置行为，不代表京东真实授权成功。
