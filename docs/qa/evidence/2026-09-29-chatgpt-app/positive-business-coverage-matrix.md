## 专用 QA 工作区的前置资源

[独立工作区只读核查](independent-qa-workspace-readonly-plan.md)及[点数/权益生产只读核查](qa-creative-points-entitlement-readonly-audit.md)证明 `demo@sn.com` 仅绑定 QA 工作区，与贵人鸟工作区无成员/身份绑定。此工作区现有测试店铺 0、商品和规范商品 0、V2 已付费权益/创意点授权/存储配额均为 0 条；余额接口返回 `unknown`/`null`。一次旧版只读/初始化后出现 `trialing` 订阅和商业设置行，它们不构成付费权益或点数授予。贵人鸟工作区历史授予累计 12600 点属于另一个租户，当前可用余额未在本矩阵核算，不能借给 QA。专用资源“稍后提供”尚未形成可验证的店铺、权益和内容对象；任何无对象 ID 的读请求只能记前置缺失或明确空态。

需要先取得并核对：

1. **专用商业权益与测试额度**：先核对资源提供方给出的工作区归属、授权/真实交易引用、批准人、额度、有效期和预算。现有双人调账要求余额已知，不能给余额 `unknown` 的 QA 工作区做首次发放；已部署首授路径要求真实支付核验。若资源为无支付 QA 额度，须先实现并审核受控首授入口且完成发布门禁；不可伪造回执、跨租户转点或直接改库。随后以 `commercial.access.get`、`creative-points.balance.get` 和服务端账本交叉核对；余额仍 `unknown` 时停止收费路径。
2. **专用可读店铺和商品**：仅绑定 `demo@sn.com` 的测试店铺账号、容量配额、测试商品货号与已确认事实；读回店铺来源、可选状态、品牌单元、listing 与规范商品关系。账号记录本身不等于已连接可读店铺。
3. **授权素材与业务对象**：可扫描的 QA 图片/表格、AI 修改授权、公开竞品来源、测试规则、两条学习建议、测试任务、内容版本、订单/导出申请等各自的真实本租户 ID。来源、版权、版本与审核责任要可读回。
4. **生产候选与中转证据**：当前 API/UI/worker 混合旧修订、发布门禁未批准；本地 143500 修复不会改变生产 API。公网 demo 数据库已到 254，本地候选要求 255；用户本轮不迁移数据库，因此现有正式 API/UI/worker 发布路径为 NO-GO，见[无迁移发布核查](20260929-no-migration-release-audit.md)。收费模型必须经已配置中转链路留下鉴权、请求、用量、成本和错误记录。图片/编辑/OCR 配置检查 `ready=true` 仅说明配置可读，未证明本轮有真实 provider 请求；缺模型/费率/成本证据时按门禁阻断。

## 143500 后续回归与发布边界

当前 143500 已验证品牌偏好空态、试用订阅的中文读取，并已开始新的全量安全调用会话；133000 的四项中文参数错误是前一版证据。需在**同一当前版本**对完整流程的成功和失败路径重新取证。首个可执行最小闭环是专用额度和测试店铺到位后，用一条 QA 商品走 `catalog.import`→`catalog.search`→`catalog.facts.confirm`→`canonical.product.consistency`，再走一条已授权素材→草稿→审核→导出，全程保留模型中转成本。知识库和商业账务另用各自测试对象执行。任何新云端 API 修复要先满足发布门禁、部署到可识别 SHA，再在真实 App 复测；本地插件安装成功本身不代表服务端已更新。当前发布结论以[无迁移发布核查](20260929-no-migration-release-audit.md)为准，正式上线判断仍需最新运行时证据。
