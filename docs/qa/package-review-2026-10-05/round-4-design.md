## D8 补丁核对

- §15“我的套餐”仅在无当前且无已付未来时提供新购；有未来无当前显示未来待生效、原合同查询与Ops受控衔接。
- §15“升级报价”同样限定新购条件，有未来无当前时禁自动插期，同级引导续购。
- §13.2 核验结果按实际状态区分立即生效、未来待生效、待依赖、待处置，不再把所有套餐核验统一称已生效。

三处与 §12.4 的新购/升档分类及 §16.1 不插期、未来额度不提前可用、正常未来合同不属于授予故障一致。D8 **closed**，保留第3轮发现过程，未改写历史报告。

## 四态交叉核对

| 状态 | 动作及标签 | 判断 |
|---|---|---|
| 无当前且无已付未来 | 查询确认后“购买套餐”，依资格走首购或正式新购；未知状态不能假装空 | 一致 |
| 有当前有效套餐 | 显示当前档位/期止，固定rank升档走剩余期报价；同档续购用floating_append，未来合同另列且不改写 | 一致 |
| 有已付未来但无当前 | “未来待生效”，显示合同/计划及受控衔接入口；禁自动插期/覆盖，未生效额度不可消费/预留 | 一致 |
| 事实未知、支付/授予异常或依赖不满足 | 显示待确认/待授予/待依赖/待处置及原订单查询，不混为当前已生效；按原请求确定结果，不能重付或自动改意图 | 一致 |

正常未来待生效与应生效却失败的异常已分别定义；不把未来合同当作空态后直接卖即时整期。核验结果中“权益包已到账”仍按该包批准时点的真实结果使用，并受逐项实际状态与不得伪称成功的通用契约约束。
