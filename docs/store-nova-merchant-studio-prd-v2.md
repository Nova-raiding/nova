# Store Nova商家工作台 v2 产品需求文档

**版本**：v2.0  
**日期**：2026-09-11  
**状态**：待评审，作为下一轮实现与验收基线  
**产品负责人视角**：商家真实经营链路、ChatGPT App/MCP、桌面运营后台、权限与上线门禁

## 1. 背景与问题定义

当前 Merchant Studio 已具备商品、任务、规则、知识、模型、账务和发布能力，但商家体验被几个结构性问题打断：

1. 登录页在用户未提交前显示错误；旧会话失效后，多个页面同时请求受保护接口，产生连续 401/403。
2. 登录成功只代表身份认证，不代表 workspace 和能力授权；前端没有把两者清晰区分，导致商家无法判断下一步。
3. 总览页、商品页、新会话入口和客服/帮助入口重复表达同一流程，信息密度高但任务路径不清晰。
4. 知识库、规则库、品类库边界不够明确；规则没有按平台规则、品类规则、广告发布规则形成商家可理解的结构。
5. 错误大多以内联错误形式出现，缺少统一的弹层、阻断页、重试和 request/trace 证据。

产品目标不是隐藏错误，而是让每个错误都变成可判断、可恢复、可审计的下一步。

## 2. 产品目标

- 商家首次打开只看到登录入口，不触发任何需要商家权限的业务请求。
- 登录状态、workspace 绑定、能力授权、平台连接和数据可用性分层表达。
- 任何 401/403 只产生一次可理解的状态转换，不出现请求级联和错误刷屏。
- 总览页聚焦经营状态与待办；商品页聚焦商品事实和素材；知识库聚焦品牌资料与规则依据。
- 知识库规则中心提供三类规则：平台规则、品类规则、广告发布规则，并显示版本、适用范围、生效状态和来源。
- 所有失败状态均有统一的反馈方式：轻量提示、弹框、页面阻断或字段错误，按影响范围选择。
- 真实 API/MCP、数据库/RLS、worker、模型中转、店铺授权和发布门禁是最终事实来源。

北极星指标是“商家从已授权资料到合规发布的成功率与耗时”。首版同时跟踪登录到首个可发布内容的 P95 时长、任务完成率、规则拦截后的修复率、发布成功率和 7 日留存。

## 3. 非目标

- 不通过前端绕过服务端权限或伪造商家数据。
- 不把 fixture 账号、fixture 店铺或本地模型回退当作生产能力。
- 不在本版本把手机/平板适配作为验收条件。
- 不在商品页复制品牌规则、平台政策或客服工具。

## 4. 核心信息架构

### 4.1 一级导航

- 运营概览：经营状态、待处理问题、连接和账务摘要。
- 商品与资产：商品事实、店铺商品、图片、素材、导入和商品营销任务入口。
- 营销任务：内容生成、审核、批量任务和任务状态。
- 发布中心：发布预览、确认、回执和失败恢复。
- 规则与检查：规则命中、检查结果和发布阻断。

### 4.2 知识库入口

“新会话”只保留一个“知识库”入口。商品、图片、素材不再作为重复的新会话入口；它们属于商品与资产域。

知识库内部包含：

- 品牌资料：品牌定位、语气、视觉要求、售后和长期事实。
- 规则中心：平台规则、品类规则、广告发布规则。
- 学习与偏好：经商家确认后沉淀的偏好和经验。
- 来源与版本：每条内容的来源、更新时间、审核状态和生效范围。

## 5. 关键用户流程

### 5.1 登录与授权

```text
打开商家 URL
  → 仅显示登录页
  → 提交账号密码
  → 服务端验证账号类型、状态和 workspace
  → 认证成功且有 workspace
  → 加载工作台数据
  → 能力不足/范围不匹配
  → 显示授权阻断页与下一步，不加载业务接口
```

要求：

- 初始未提交状态不显示登录失败。
- 表单校验错误显示在字段旁；认证失败显示在登录卡片内；会话失效显示为一次弹框并回登录页；权限不足显示阻断页。
- 账号类型不是 merchant、账号未激活或未绑定 workspace 时，不进入总览页。
- 无 workspace 时提供“查看审核状态/申请绑定/联系平台管理员”动作，不把阻断伪装成普通错误。
- 登录成功后首个请求必须是 session/context 校验；通过后才并行加载业务数据。
- 任一受保护请求返回 401/403，统一终止当前数据加载批次，清理客户端 session/context，并回到登录页或授权阻断页。
- 403 必须按 reason code 路由：会话失效才回登录页；scope/capability 缺失进入授权阻断页并保留 request ID。
- 同一失效事件只触发一次；后续请求在客户端短路，不继续访问 API。

### 5.2 商品工作流

```text
商品与资产 → 选择平台/店铺 → 同步或导入 → 核对商品事实 → 选择商品 → 创建营销任务
```

商品页必须清楚区分：

- 商品事实：标题、价格、库存、规格、材质和图片。
- 素材权益：来源、授权、扫描和可用状态。
- 店铺身份：workspace、platform、account_id 和授权 revision。
- 数据新鲜度：实时、旧快照、读取失败和未配置。

### 5.3 知识库与规则中心

规则中心默认展示三个分类卡片或 Tab：

| 分类 | 作用 | 示例 | 触发时机 |
|---|---|---|---|
| 平台规则 | 平台字段、内容格式、交易和发布要求 | 淘宝标题限制、京东字段要求 | 选择平台/发布前 |
| 品类规则 | 某品类必填事实、属性和禁用表达 | 防晒外套材质、鞋靴尺码 | 选择品类/生成前 |
| 广告发布规则 | 广告法、促销表达、功效宣称和风险词 | 极限词、绝对化承诺、疗效表述 | 生成/审核/发布前 |

每条规则必须展示：名称、分类、版本、适用平台/品类、状态、更新时间、来源引用、检查结果和阻断原因。规则缺少来源或未验证时，只能作为核对依据，不能标记为可执行。

### 5.4 错误反馈模型

| 错误范围 | 展示 | 必须提供 |
|---|---|---|
| 字段输入错误 | 字段旁 inline error | 修正指引、焦点定位 |
| 单次可恢复动作失败 | Toast/轻量弹框 | 原因、重试、幂等保护 |
| 页面数据读取失败 | 页面状态卡 | 数据集、request ID、重试、旧快照说明 |
| 401/403 | 全局会话/权限阻断弹框或页面 | 重新登录、查看权限、workspace 范围 |
| 模型/支付/发布门禁 | 阻断卡 | 配置缺口、下一步、不会扣费/写入的承诺 |

错误文本不得只显示 HTTP 状态码；日志可保留完整技术信息，商家看到的是可执行的业务语言。

## 6. 数据与权限契约

所有商家请求必须由服务端从有效 session 推导身份和 workspace。客户端传入的 workspace 只能作为非同源 API 的显式范围，不能覆盖 HttpOnly 商家会话的权威范围。

每个业务调用需要形成：

```text
ChatGPT/App 入口 → MCP/HTTP 方法 → 身份认证 → workspace/account 范围 → 能力授权 → 数据库/RLS → worker → 审计 → UI 状态
```

关键规则：

- merchant 账号必须为 active 且至少绑定一个 active workspace。
- `platform-accounts`、`sync-jobs` 和 MCP 读取必须使用商家 scope 对应的能力投影。
- 403 必须区分：会话失效、workspace 范围不匹配、能力缺失、账号未激活和平台未配置。
- 任何空列表必须标记为真实空数据、读取失败、未授权或等待加载，不能把失败显示成“暂无数据”。
- 所有写入操作保留 request_id、trace_id、revision、幂等键和审计事件。

## 7. MVP 交付范围

### P0：登录链路与错误收敛

- 统一 session/context bootstrap。
- 登录前禁止业务请求。
- 401/403 单事件短路、清理和回登录页。
- workspace/能力阻断页。
- 登录、权限、API 错误回归测试和真实桌面验收。

### P1：信息架构收敛

- 总览移除宣传型 welcome panel 和环境 banner。
- 新会话只保留知识库。
- 删除客服回复、帮助与诊断的重复导航入口。
- 商品页重命名和说明聚焦商品事实与素材。

### P1：规则中心

- 规则三分类数据契约：`platform`、`category`、`advertising_publish`。
- 分类筛选、平台筛选、关键词搜索和规则详情。
- 规则版本、来源、状态、阻断原因展示。
- 规则治理包含创建、审核、生效、冲突优先级（平台 > 品类 > 广告发布）、回滚和租户覆盖；商家端只读，平台运营端负责发布。
- 生成前和发布前分别调用对应规则检查。

### P2：引导页

- 新会话引导页独立为可选流程，不嵌入总览首屏。
- 根据 workspace 状态展示“完善知识库”“连接店铺”“同步商品”“开始任务”的下一步。
- 引导状态可关闭、可恢复，不能替代真实权限和数据状态。

## 8. 验收标准

### 登录

- 空白打开登录页：无业务 XHR/fetch、无 inline-error、无 401/403 控制台错误。
- 空提交：只显示字段校验，不调用登录接口以外的业务接口。
- 错误账号：登录卡片显示可理解错误，页面不进入工作台。
- 已激活且绑定 workspace 的本地账号登录后，`/platform-accounts` 和 `/sync-jobs` 返回成功。
- 账号无 workspace：显示授权阻断页，不产生级联 403。
- 会话过期：最多一次鉴权失败后停止后续请求，回登录页。

### 导航与页面

- 总览不存在 `welcome-panel` 和 `environment-banner`。
- 新会话导航只有知识库。
- 侧边栏不出现客服回复、帮助与诊断。
- 商品页、知识库、规则中心各自有唯一清晰职责。

### 规则

- 三类规则可切换、筛选和查看详情。
- 未验证规则不能进入“可执行”状态。
- 规则失败显示规则名称、版本、来源和下一步。

### 运行门禁

- TypeScript 类型检查通过。
- 商家工作台单元/API 测试通过。
- 真实 Docker API、UI、worker 健康检查通过。
- 桌面浏览器完整登录、商品、知识库、规则、任务和退出流程通过。
- 生产模式缺失模型中转、支付、OAuth、对象存储或扫描器配置时必须 fail-closed，并明确显示阻断原因。

## 10. 指标与上线门禁

- 登录页空载业务请求数：0。
- 未授权状态下重复 401/403 请求数：0；单次鉴权失败后的后续受保护请求：0。
- 登录成功到首个可交互工作台的时间：P95 < 3 秒（本地 fixture 基线）。
- 页面错误中可恢复错误占比：100% 提供下一步。
- 规则命中结果可追溯率：100% 有版本和来源。
- 发布前规则阻断绕过率：0。
- 生产发布门禁：真实模型中转鉴权、五模态用量/成本证据、平台 OAuth、对象存储/KMS、扫描器、支付和发布回执全部通过；任一缺失即阻断。

## 11. 实施顺序

1. 先完成 session/context bootstrap 和 401/403 单事件短路。
2. 修复账号授权数据和本地 fixture 演示链路，完成登录后 API 200 验证。
3. 收敛总览与导航，移除重复入口和宣传组件。
4. 落地规则三分类数据契约和知识库规则中心。
5. 统一错误状态组件和审计证据展示。
6. 运行桌面浏览器全流程、API/MCP 契约、worker 和容器健康检查。
7. 生产配置门禁全部通过后，再进行发布 canary。

## 12. 产品决策

本版本的核心决策是：商家工作台围绕“知识与规则 → 商品事实 → 营销任务 → 检查 → 发布”组织；身份、workspace、能力和数据状态必须分层表达；错误必须推动恢复动作；任何真实能力缺失都 fail-closed。这样可以同时解决用户反馈的界面重复、登录不可用、403 刷屏和规则库缺失问题，并让后续开发拥有可验证的产品边界。
