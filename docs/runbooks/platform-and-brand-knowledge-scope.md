# 平台规则与品牌规格作用域契约

## 目标

平台运营上传一次平台规则，发布后所有商家按平台读取；运营上传的品牌规格只对绑定该品牌的商品和任务生效。

## 数据边界

平台规则和商家工作区规则不能共用同一条 workspace-only 数据记录：

- `platform_rule_versions`：平台级、按 `platform` 隔离；
- `platform_rule_audits`：平台规则的追加审计；
- `knowledge_assets`：商家/品牌知识资产；品牌资产必须带 `brand_id`；
- `knowledge_documents`：索引文档必须保留 `brand_id` 和 `workspace_id`；
- 商家工作区规则继续使用现有 `rule_pack_versions`，不能冒充平台规则。

## 平台 Markdown 导入

上传文档后：

1. 读取 `## PDD-*` 规则卡；
2. 校验平台、官方来源、核验时间和卡片编号；
3. 生成草稿，默认 `status=draft`；
4. 保存原文片段和 SHA-256 checksum；
5. 运营预览拆分结果；
6. 规则管理员审核并发布；
7. 发布事件写入追加审计；
8. 商家读取时只返回 `status=active` 且在有效期内的规则。

导入不能因为 Markdown 解析成功就自动激活，也不能把 `manual://` 记录当成官方已验证规则。

## 商家读取

商家请求包含：

```text
workspace_id
platform
brand_id（可选但商品任务中应优先提供）
category（可选）
```

服务端按以下顺序合并上下文：

1. 当前平台的已发布平台规则；
2. 当前工作区的已批准规则；
3. 当前商品绑定品牌的已批准、权益已清除品牌规格；
4. 当前商品/素材事实和任务上下文。

未绑定品牌、品牌冲突、品牌资产未审批、权益未确认或索引未完成时，不得把品牌规格注入生成上下文；应返回明确的待处理状态。

## 权限和 RLS

- 平台运营可创建、审核和发布平台规则；
- 商家只能读取已发布平台规则；
- 商家不能修改平台规则；
- 品牌规则写入必须验证品牌所属关系和运营权限；
- 商家只能读取自己工作区可见的品牌资产；
- 不允许用客户端传入的 `brand_id` 绕过商品/任务品牌关系；
- 平台规则读取不代表商家获得平台店铺授权，也不打开六平台自动同步或发布。

## 上线验收

- 上传 `拼多多平台规则.md` 后生成 36 条草稿；
- 草稿不出现在商家可执行规则中；
- 发布后两个不同工作区都能读取拼多多规则；
- 淘宝等其他平台读取不到拼多多规则；
- 品牌 A 规则不会出现在品牌 B 商品任务；
- 品牌未确认时生成流程显示阻断或待处理，而不是静默使用品牌规则；
- 停用/过期后的规则不再进入新任务，但历史审计仍可查询。
