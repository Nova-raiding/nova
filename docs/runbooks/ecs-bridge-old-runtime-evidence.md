# B bridge: old-runtime evidence precheck

This precheck is for the **historical, unlabeled seven containers** and the external HTTPS gateway observed on 101. It does not migrate the database, stop containers, install a helper, sign a journal, or authorize cutover. Run only after a separate operator review of free disk and protected output paths. It must run as root on Linux; evidence and archive must be root-owned, mode 0600, under a root-owned non-group/world-writable directory. Do not copy an inspect JSON or `.env` into tickets or chat.

1. Independently record the full old source Git SHA and full running gateway container ID. Verify that the exact API `RELEASE_GIT_SHA` corresponds to the reviewed source revision. The program fails closed on a mismatch.
2. Before creating an archive, reserve space for the three old image IDs (API, worker, gateway) plus archive and verification headroom. `docker image inspect .Size` is only a logical estimate, not an exact archive size. `docker save` is an explicit, separate production write; this precheck never invokes it.
3. Save exactly those three **local image IDs** into one protected Docker archive, with `umask 077`. Do not substitute a guessed `repo@sha256` value. The archive verifier checks the manifest's image-config hashes and each uncompressed layer diffID against its bytes, then records the whole archive SHA-256. A true registry digest requires a registry manifest obtained and checked separately; a local image ID is not one.
4. Invoke `node infra/scripts/ecs-bridge-old-runtime-evidence.mjs freeze --output /protected/old-runtime.json --gateway-id <full-container-id> --source-git-sha <full-git-sha> --archive /protected/old-images.tar`. `freeze` writes a new 0600 JSON file, never overwrites one, and records only hashes, identities, aliases and sizes—not environment values. `verify --evidence /protected/old-runtime.json --archive /protected/old-images.tar` recaptures the running topology and checks both runtime and archive have not drifted.

The JSON intentionally says `signed:false` and `cutover_authorized:false`. It is review evidence, **not** the signed preidentity map/capsule. The B runner must separately require its signed journal, nonce, exact seven-container recovery state, DB schema 242, a healthy real scanner canary and public readiness/identity acceptance. Any mismatch or missing archive blocks B. If an original container ID or gateway is lost, this archive does not magically restore that ID: stop automatic recovery and use an explicitly reviewed manual restore. Do not call the archive digest a registry digest or claim this precheck proves source-to-image build provenance.
