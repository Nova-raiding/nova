# 桌面端低成本交付迁移方案

## 目标

只交付桌面 ChatGPT/Codex 插件和 Store Nova 商家后台，不依赖 ChatGPT Business/Enterprise/Edu 工作区，不把充值或六个平台授权放进 ChatGPT 云端插件。

## 运行边界

```text
桌面 ChatGPT/Codex
  -> 本地 stdio bridge
  -> HTTPS /mcp
  -> Store Nova 商家后台与 API
  -> 支付服务商回调、对账和入账
```

桌面插件可以读取余额、订单状态和内容工作流状态；充值入口只负责把用户引导到商家后台。插件不承载收款、不生成支付签名、不保存支付宝或微信密钥。当前账务 UI 的套餐按钮统一打开 `https://yxsona.com`，支付必须在登录后的商家后台完成。

## 商家安装流程

1. 商家安装 `merchant-marketing` 桌面插件。
2. 商家登录 Store Nova 商家后台。
3. 点击“连接本地插件”。后台通过同源会话申请一次性短期 access/refresh 凭据。
4. 可信安装器将凭据写入当前 macOS 用户的系统凭据存储；不得复制到聊天、仓库或普通配置文件。
5. 完全退出并重新打开 ChatGPT/Codex，开启新会话。
6. 输入“查看我的余额”验证工作区身份和余额状态。

## 充值流程

1. 插件显示余额不足或“支付请在商家后台完成”。
2. 商家点击“打开商家后台”。
3. 商家后台创建服务端 SKU/充值订单并展示支付入口。
4. 商家在后台完成支付宝或微信支付。
5. API 验证服务商签名回调、幂等键和金额；对账成功后才入账。
6. 商家返回插件查询订单和 `billing.status`。

`PAYMENT_MODE=fixture` 只能用于本地测试；生产必须是 `provider`，并具备 HTTPS callback、签名密钥、查单、退款和对账证据。待支付、支付成功但 grant 未到账、回调未知都不能显示为“已充值”。

## 六个平台的运营替代

桌面插件不提供六个平台店铺 OAuth、库存/订单同步或自动发布。平台运营后台负责人工收集公开商品资料、核验平台页面、维护证据并向指定商家发布已审核数据。商家侧只消费工作区内已授权、已审核的数据。

## 上线门禁

- 插件包不含密码、Cookie、支付密钥、共享 token。
- access token 过期能轮换；refresh 失效要求重新登录；账号停用立即拒绝。
- 商家 A 无法读取商家 B 的工作区、订单、余额或素材。
- 本地环境不回退到生产共享 fixture token。
- 生产 API、支付回调和商家后台均使用 HTTPS。
- `npm run typecheck`、`npm run test:release-gates`、插件安装 smoke、桌面浏览器验收和 ECS 健康检查全部通过。

## 不采用的方案

- 不购买 Business 账号作为桌面插件的前置条件。
- 不把 ChatGPT 云端 MCP OAuth 当作本地安装授权。
- 不让 ChatGPT 直接扣款。
- 不删除服务端鉴权、RLS、审计或支付回调验证来降低安装成本。
