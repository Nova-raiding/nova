# Knowledge embedding production gate

Knowledge search remains lexical unless the release has a dedicated durable background-index authorization, a pre-provider budget reservation, an attributable relay usage/cost settlement, and reconciliation for ambiguous provider outcomes. `EMBEDDING_MODEL` alone never enables vector indexing.

The configured Wormhole relay catalog supplied for this deployment lists `qwen3.7-text-embedding-flash` and `qwen3.7-text-embedding`. The default candidate is `qwen3.7-text-embedding-flash` with 1024 dimensions, matching the supplied `POST /v1/embeddings` request shape (`input`, `dimensions`, `encoding_format: float`). The client sends a single input as a string and batches as an array. Its idempotency identity retains the prior array-shaped canonical body so an ambiguous attempt re-enqueued across a deployment keeps the same key. A local contract test verifies this key and the URL, body, response dimensions, request ID, usage and cost wiring; it does not prove live relay authorization, pricing, or how the relay handles an existing key with a different body shape. Keep `KNOWLEDGE_VECTOR_INDEX_ENABLED=false` until a real authenticated relay request, cross-release idempotency behavior, cost evidence, budget cap and signed release evidence are available.

The vector-index configuration contract requires `embedding_model`, `embedding_dimensions`, `embedding_max_request_cny`, and an explicit `knowledge_vector_index_enabled`. The ECS Compose production layer maps the candidate model, dimensions, version, request cap, and explicit flag to both API instances; the automation worker receives the model, dimensions, version, flag, and relay connection needed to execute indexing. The API alone receives the per-request budget cap and relay cost-evidence switch. Relay URL, exact allowed hostname, and bearer key are passed from the root-owned, mode-0600 `ECS_PRODUCTION_ENV_FILE`; the key is never stored in this repository. `.env.example` documents the relay URL and hostname, candidate model `qwen3.7-text-embedding-flash`, 1024 dimensions, version `v1`, and disabled indexing default. The request-cost cap and relay credential must be supplied through protected production configuration before any activation review.

Lexical knowledge search remains production-usable when the flag is `false`; `/readyz` and `platform.model.status` report vector indexing as an optional capability. Missing or placeholder embedding credentials do not start indexing while the flag is `false`. If the flag is set to `true`, the API and automation worker require the authorization, positive budget reservation cap, relay cost evidence, usage/cost settlement, and reconciliation workflow below, and readiness remains fail-closed until all of them pass. Compose wiring alone is configuration closure, not evidence of an authenticated provider request or permission to enable the flag.

Current production search remains lexical even if background vectors are written: `catalog.search` does not create a query embedding or pass one to the knowledge repository. It filters the product page by text before knowledge lookup. Do not describe enabling indexing as semantic search. A billable semantic query needs an explicit authorized method, durable action and budget reservation, idempotent relay request, settled usage, model/version-matched vector retrieval, and an unknown-outcome path before it can be enabled.

Before enabling, verify all of the following against the final release: the automation worker uses its role-specific bearer token and HMAC secret for embedding admission, outcome, and embedding model-usage callbacks; the worker obtains a signed workspace-scoped authorization before calling `/embeddings`; the API persists the action and budget reservation before provider dispatch; the provider request ID, numeric token usage, observed CNY cost, model and run key settle through the model usage ledger; retries reuse the action/idempotency identity; revocation and document revision/hash changes prevent vector writes; unknown outcomes enter reconciliation without a second provider call. The API temporarily accepts the generation role on these routes for rolling-deploy compatibility, but the automation worker must never receive generation credentials. Then generate release-bound embedding relay evidence. A configured model, a successful direct curl, or a stored vector does not satisfy this gate.
