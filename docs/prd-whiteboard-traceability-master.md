# PRD + 白板需求总追踪矩阵

审计日期：2026-08-25  
审计方式：四个并行代理分别核对 FR-01～05、FR-06～10、FR-11～15/NFR、白板第 24 章；主线程复核代码和测试。

> 范围校正（2026-08-27）：当前产品目标为六个平台（京东、淘宝、天猫、拼多多、小红书、抖音）；本文旧版“四平台”表述均按历史 PRD 解释，当前验收还额外要求每个平台的 `media_upload` production canary。

## 判定口径

- **已完成（本地）**：有代码/API/UI 和自动化测试证据；不等于真实生产通过。
- **部分完成**：有骨架或局部路径，但缺少 PRD 明确字段、状态、用户交互或完整验收。
- **未完成**：没有可证明的实现路径。
- **外部门禁**：必须依赖真实平台、云资源、模型、扫描器、支付或人工/法务证据。

## 白板追踪

### 建档问题 1–30

白板 1–16 的品牌、语气、禁用项、冲突和权益已有数据结构与 MCP 路径；品牌资料候选抽取、逐字段确认，Logo 默认不改色/变形/重绘、品牌色集合、字体授权状态和生成前阻断，以及历史素材优秀/不喜欢评价、原因与任务引用/排除已完成本地闭环。像素级成片品牌一致性、图片/扫描件识别仍为部分完成或外部门禁。白板 17–30 的商品、SKU、同步和事实确认已有本地骨架；真实平台数据、活动价生命周期、SKU 图片回读和完整确认卡仍为部分或外部门禁。

### 营销任务 14 部分

会话、自然语言、任务记录、方向、方案确认、内容版本、审核入口、导出和发布门禁已有本地路径。动态追问已支持阻断/推荐/可选、每轮最多 4 问、原因/后果、回答后重算和非阻断“稍后补充”；六类审核报告已统一返回并在 Merchant Studio 展示。P1/P2 可知悉或带理由接受并保存处理人、时间、原因和版本修订；P0 只能修改后复审，不能绕过。素材授权/规则冲突追问、真实视觉/视频模型质量和真实平台预检仍未完成。主图目前已可在 Codex App 显示，但本地 fixture 不代表真实图片模型质量。

### 第 24.3 特殊要求

自动清理已降为 P2；单商品 Banner 与多商品任务已拆分；版权检查明确只做授权声明完整性；规则版本和来源已有，但自动规则采集未实现；Markdown/JSON/ZIP 已有，PSD/AI/EPS 等源文件后置。

## 明确的生产阻断项

1. 六个平台真实 OAuth、同步、创建/更新、查询、撤权、媒体上传和回执 canary。
2. 真实云 50 家容量及向 500 家扩容的 6 小时稳定性/公平性报告。
3. 生产 LLM/图片模型、对象存储、KMS、Vault、扫描/OCR、OTel/告警和支付服务。
4. 真实 Codex App 黑盒回归：断网、恢复、切会话、弱网、可访问性和所有 P0 产物展示。
5. 10 个 P0 黄金任务和六平台各 5 个连接器样例的持续 Eval。

## 本轮可直接落地的修复

- 店铺分析已增加商品风险摘要和有证据的 recommendations。
- 规则优先级/有效期执行语义、审核 finding 证据字段、素材重复上传去重已完成本地实现并通过回归；真实平台/云/供应商门禁仍未完成。
- 服务端已支持 `REQUIRE_APPROVED_ASSET_FOR_GENERATION=true` 素材权益门禁；方案确认后的商品/SKU/价格/库存/规则/素材快照已冻结；内容生成和 Codex 提交已增加结构化 schema 校验。
- 竞品调研结论已落到商品交付包、风险优先分析和主图套图路线。

## 不能误报为完成

fixture、fake connector、本地/Compose 压测、模拟支付、SVG/本地图片、MCP 工具存在、Merchant Studio 页面存在，都不能单独证明真实平台生产可用、真实 AI 商品图质量、真实版权或 500 家云容量通过。
